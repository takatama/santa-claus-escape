## 起動と操作

既存の4190番が同じ試作を配信している場合はそのまま使います。停止していてポートが空いている場合のみ、Node.js 24以降で以下を実行します。4186番を使用・停止しません。

```powershell
cd 'C:\Users\takat\OneDrive\ドキュメント\ChatGPT\santa-clause-escape\illustrated-prototype'
npm start -- --port 4190
```

- 森の箱を触るか「箱を大きく見る」で調査します。
- 四輪の列を上へ回すと下の数字が中央に来ます。下へ回すと上の数字が中央に来ます。上下ドラッグ・↑↓・数字キー・左右の桁移動も使えます。
- 「この数字で試す」は錠のすぐ下にあり、最初から試せます。手がかりの閲覧は解除条件ではありません。
- 「調べてみる」の1回目で四つの手の絵「グー、チョキ、パー、グー」、2回目で「負けるが勝ち」、3回目で「指の数があなたをみちびく」が現れます。雪は曲線に沿って徐々に取れ、周囲に不規則に残ります。任意の場所を自由にこする操作はありません。
- 「見えた文字を読む」には、その段階で発見した絵と文字だけが入ります。ヒントをすべて見なくても数字を試せます。
- 最後の手がかりまで調べた原作の第4段階で、誤った四桁を試した場合だけ、原作の誤答ヒント「負けるが勝ちなので、グーに勝つのはチョキのようです。」を表示します。初期や途中の段階で先に表示しません。
- 「森に戻る」やEscapeで数字と発見済みの手がかりを保持します。雪を払う途中で閉じた場合は、押した一段階を完了します。
- 解錠だけではふたは開きません。森でふたを上へ引き、途中停止・逆戻し、ボタン・スライダー・キーでも操作できます。全開100%で「き」「だ」の紙を一度だけ得ます。
- 「最初に戻す」で雪・数字0000・錠閉・ふた0%・紙0枚へ戻ります。進行中の演出と誤答表示も取り消します。

## 原作と素材

`prototype/full-scenario.js`と`prototype/reference/legacy-index.js`の日本語`yellowBox1–4` / `yellowNotSolved4` / 解錠判定 / 授与文字を根拠としています。四つの手は既存の日本語シナリオと同じ「グー、チョキ、パー、グー」に固定します。原文と誤答ヒントは[box-math.js](box-math.js)の`EXAM_CLUES`と`WRONG_HINT`に保持しています。答えや新しい謎、台詞、救出の進行を追加していません。

黄色い本体・ふた・じゃんけんの絵は、制作時に組み込みimage_genで用意し、[assets](assets/)の`yellow-body.png`、`yellow-lid.png`、`rock.png`、`scissors.png`、`paper.png`に保存しました。制作プロンプトと参照元は[assets/PROMPTS.json](assets/PROMPTS.json)に記録しています。四つの絵は横一列に並べ、最初と最後のグーには同じ素材を使います。森・球・枝は既存素材を再利用します。正確な文字、数輪、雪は分離してコードで描き、元の参照画像は上書きしません。

作業は`illustrated-prototype`内です。既存ゲーム、paper-prototype、threejs-prototype、元の参照画像を変更しません。ゲーム実行時の生成AI・外部API・音声、サーバー機能、公開・デプロイは対象外です。

手の絵は全体の高さではなく、手のひらの幅を基準に大きさを揃えます。チョキの伸ばした指とパーの広がりを保ち、画面幅に合わせる時も四つの手を同じ倍率で縮めます。チョキは描画時に左右反転し、グーとパーは右手の素材をそのまま使います。2026-10-09にパーの反転を訂正し、四つとも右手に統一しました。雪払いも描画と同じ位置と寸法を使います。
