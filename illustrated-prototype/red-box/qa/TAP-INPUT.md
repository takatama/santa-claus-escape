# 赤箱のタップ入力への見直し — 2026-10-07

この後、初見では何をすればよいか分からないという利用者の指摘を受け、入口を「箱を調べる」に変更し、数字欄は「数字を合わせる」から表示するようにした。[最新の操作案内・確認](../../INTERACTION-GUIDANCE.md)。本記録のタップ選択自体は維持するが、開始時の本文や数字欄の見せ方は最新記録が優先。

## 今回の判断

この絵の試作では、スマートフォンの標準操作を数字のタップ選択にした。四つの数字窓を錠前として残し、細いダイヤルを連続して回す操作の代わりに、選んだ桁へ0〜9を直接設定する。指の移動量で値が変わる方式より、狙った数字を明示して合わせることを優先した設計判断であり、初見利用者との比較試験による結論ではない。

数字窓は初期値0000。窓をタップすると0〜9を2行5列で表示し、一つ選ぶと次桁へ進む。4桁目の選択後は選択欄を閉じる。数字をそろえただけでは解錠せず、「カギを試す」の操作で判定する。画面上の数字選択にテキスト入力欄へのフォーカスは使わない。

直接入力は折りたたみで残した。開くだけでは入力欄をフォーカスしない。必要な利用者が入力欄を選ぶことで使える。タップ・直接入力・箱に描く数字は同じ値を共有する。原文、解答、文字の獲得条件、開閉の仕掛けは変えていない。

## 残る評価

スマートフォン幅のブラウザ検査であり、実端末の指による精度、OSキーボードの出入り、スクリーンリーダーの読み上げは未検証。標準経路に入力欄のフォーカスがないことを確認した。

四桁の選択と明示的な確定を確認できたが、旧ダイヤルより楽しいか、次桁への自動移動が初見で分かるかは利用者観察が必要。絵の寸法を固定しているため、小さい画面では手がかりと数字操作へ縦にスクロールする。画面上のテンキーは絵に重ねず、選択中だけ表示する。

初版の直接入力・空欄初期値の検査は [VERIFICATION.md](VERIFICATION.md) に歴史的な記録として保持した。現在の入力方法と0000へのリセットは本記録が最新。旧画像の森・サンタ・ふたは変わらないが、入力UIと箱に描く初期数字は更新されている。
