三つの箱から得た六枚の紙を並べ、ひみつの言葉を伝える場面です。深い青の森と球内のサンタを使い、文字の紙を指で動かせます。全編の接続モードと、六枚を初めから持つ独立試作を用意しています。原作の三箱は自由な順番で調べられます。

## 起動と操作

現在の4190番の独立プレビューを再利用します。停止していてポートが空いている場合のみ、Node.js 24以降で以下を実行します。4186番を使用・停止しません。

```powershell
cd 'C:\Users\takat\OneDrive\ドキュメント\ChatGPT\santa-clause-escape\illustrated-prototype'
npm start -- --port 4190
```

- 通常のURLは、六枚を取得済みとした独立場面から始まります。手元に「す」「だ」「い」「よ」「き」「だ」の紙があり、六つの枠へ置けます。他のページで箱を開けた記録を読み込む入口ではありません。
- 紙を枠へドラッグするか、紙を選んでから枠をタップして置きます。すでに置いた紙を別の紙の枠へ移すと入れ替わります。手元から置き換えた場合は、もとの紙が手元へ戻ります。
- 選んだ紙をもう一度タップすると選択を解除します。別の置き済み紙を選びたい時も、いったん選択を解除してからその紙を押せます。
- 左右キー・移動ボタンでも位置を変えられます。「手元へ戻す」で選んだ紙を枠から戻せます。
- 六つの枠がそろったら「この並びで伝える」で送信します。並べただけでは呼びかけを実行しません。
- 常時使える「ひみつの言葉」入力欄と「伝える」でも送信できます。紙の並べ替えは必須ではなく、紙順から入力欄へ自動代入しません。自分で入力した言葉は、紙を動かしても上書きしません。
- 空欄や誤った言葉を送信した場合は、その場で見直せます。紙・並び・入力を消しません。
- 正しい呼びかけを送信すると枝の奥に光がともり、成功を表示して約1.1秒後に発見の場面へ自動で進みます。入力と紙の並びの両方に対応し、接続モードでは発見済みなら [会話の保存段階](../witch/README.md) へ進みます。成功済みの状態を見返す時は自動遷移せず、下端の大きな主操作から続きを選べます。保存不可の場合は自動遷移を止め、理由を表示します。サンタは救出を始めるまで球内です。
- 「最初に戻す」で、この入口の初期状態へ戻します。通常は紙六枚が手元へ戻り、`?papers=none`では紙なしのまま、枠・入力・呼びかけ結果を消します。他の試作の進行は変更しません。

`?papers=none`は、紙をまだ取得していない状態でも既知のひみつの言葉を直接入力できることを確認する独立入口です。正しい呼びかけで紙を授与したり、箱を開いたことにしたりしません。ユーザーの他の試作の進行を消す操作はありません。このページの並び・入力・呼びかけ結果は全編へ保存・引き継ぎしません。

## 原作と素材

`prototype/full-scenario.js`の紙と六文字の説明、`prototype/reference/legacy-index.js`の日本語`allOpened`と`witch`、`design/reference/witch_usersays_ja.json`の呼びかけ候補を根拠としています。原文と判定は[word-math.js](word-math.js)に保持しています。新しい謎・答え・救出の進行を追加しません。

紙は赤箱の「す」「だ」、青箱の「い」「よ」、黄箱の「き」「だ」です。二枚の「だ」も原作の出所を保ち、`red-1`と`yellow-1`という別IDで扱います。文字が同じことを理由にまとめたり、一枚を複製して六枚にしたりしません。

原作の「だいすきだよ」「ダイスキダヨ」「大好きだよ」を受理します。判定は現行ゲームと同じくNFKCによる文字幅の正規化、空白の除去、カタカナからひらがなへの変換を行った完全一致です。余分な言葉を含む文章を部分一致で正解にはしません。原作どおり、紙の取得や並べ替えを呼びかけの必須条件にしません。

森・球・枝は既存の素材を再利用し、新しい画像素材は作りません。紙と正確な文字はHTML/CSSで表示します。作業は`illustrated-prototype`内に限ります。既存ゲーム、paper-prototype、threejs-prototype、元の参照画像を変更しません。ゲーム実行時の生成AI・外部API・音声、サーバー機能、公開・デプロイは対象外です。

2026-10-09に解答後の誘導を更新しました。[自動遷移・三箱の次操作・確認と限界](../qa/POST-SOLVE-NAVIGATION.md)。以下の2026-10-08のリンク表示方式は当時の検証記録です。

`npm run check`で構文とローカル参照、`npm test`で既存の状態・幾何と六枚のID・移動・任意の直接入力・完全一致判定を確認します。素のHTML/CSS/JavaScriptのためビルドは不要です。

2026-10-08に実ブラウザの通常幅1280×720と390×844で確認しました。[スクリーンショット](qa/2026-10-08/)を保存し、以下の範囲を確認しています。

- ドラッグとタップによる配置、二枚の「だ」のID保持、左右キーによる一段移動と占有枠の交換、移動後のフォーカス保持、手元への復帰、枠外へ放した時の復帰、手元から占有枠へ置いた時の元の紙の復帰。
- 紙を動かしても入力済みの「まだ」を保持。空欄と誤答は呼びかけへ進まず、390×844では六枚の誤った並びを交換して正しい並びにしても、送信するまでは呼びかけ結果が変わらないこと。
- 全枠が空のまま、空白を含むカタカナの直接入力で成功。紙なし入口では漢字の直接入力を連続送信しても紙は0枚で、サンタは球内、枝は閉じたままであること。
- 発見リンクが既存の発見試作`index.html`へ進み、六枚の紙のページへ戻ると独立初期状態から始まること。全編への進行保存はありません。
- ページ幅は通常画面で1265px（表示幅1280px以下）、390px画面で375px（表示幅390px以下）。横はみ出しはなく、ブラウザログの警告・エラーは0件でした。

これはブラウザでの画面・操作確認です。スマホ実機の指操作、初見の使いやすさ、親子での体験、IME実キーボードの変換・確定、動きを減らす設定での実ブラウザ操作は未検証です。
