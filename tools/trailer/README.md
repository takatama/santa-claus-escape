# 紹介動画の制作ツール

記事用動画の制作で使った処理から、収録・音ズレ測定・編集を切り出しました。
ゲームのコードや通常の保存データは変更せず、毎回新しいブラウザーで操作します。
完成動画や録画フレーム、FFmpeg本体、フォントはこのリポジトリに含めません。

## できることと範囲

- 英語版 `/en` の表紙→サンタ→箱選択→赤い箱の不正解ダイヤル操作を収録。
- CDPの映像時刻と、MediaRecorderで収録したゲーム音を合わせる。
  Playwright標準の動画録画には音が入らないため、別々の時計を補正する必要があります。
- 実際に再生したWeb Audioバッファーと録音を相互相関で比較し、テイクごとに補正量を測定。
  エンコード後も比較し、残差30ms未満・相関0.98超を必須とします。
  本収録では10秒以上離れた参照を含む2点以上を検査します。
- JSONの編集指定から1920×1080、16:9、30fps、H.264/AACのMP4とサムネイルを生成。
  クロップ、滑らかなズーム、上部の読みやすい字幕、原画を使った終了画面、BGMのダッキングに対応。

**英語版の自動収録に限定**しています。日本語版は物語音声の再生方式が違い、
HTMLAudioの録音自体はできますが、この同期検査用の参照取得には未対応です。
一般のサイトや別の音声グラフで動く汎用レコーダーではありません。

## 準備

Node.js 24以降、Python 3.11以降、FFmpeg（libx264/AAC/Opus/sidechaincompress対応）が必要です。
FFmpeg 7.1、Pythonの依存はrequirements.txtの版で動作確認しました。
Linux/macOSは未実行です。日本語字幕には日本語を含むフォントを指定してください。

リポジトリのルートで実行します。

```sh
npm ci
npx playwright install chromium
python -m pip install -r tools/trailer/requirements.txt
python -m unittest discover -s tools/trailer -p 'test_*.py'
```

FFmpegをPATHに置くか、Pythonコマンドのサブコマンドより前に
`--ffmpeg /path/to/ffmpeg` を渡します。環境変数 `FFMPEG_BINARY` でも指定できます。
ブラウザーの場所を指定する場合は収録コマンドに `--browser /path/to/chromium` を追加します。
個人のパスや特定のブラウザーバージョンはコードに固定していません。

## 1. 試し撮りを検証する

```sh
node tools/trailer/capture.mjs --trial --out .trailer/trial
python tools/trailer/trailer.py sync .trailer/trial
```

`sync-check.json` の `pass: true` と、`synced.mp4` の映像・声を確認します。
検査が失敗したら本収録には進みません。固定の遅延値や閾値の緩和で通さず、
出力されたエラーと音声経路を調べてください。再試行には新しい出力先を使います。

## 2. 本収録を検証する

```sh
node tools/trailer/capture.mjs --out .trailer/session --trial-report .trailer/trial/sync-check.json
python tools/trailer/trailer.py sync .trailer/session
```

成功した試し撮りと同じGitリビジョンであることを確認してから起動します。
同じマシン・ブラウザー・依存を使い、変更したら試し撮りをやり直してください。
試し撮りに通っても、本収録の補正量は新たに測定します。

`capture.json` にはリビジョン・ブラウザー版・操作時刻・音声参照を残します。
`synced.mp4` の0秒は最初の映像フレームです。
操作や発話の映像内時刻は `(イベントのtまたはscheduledT - frames[0].t) / 1000` です。
検査は音声と記録時刻の一致を測るもので、画面の内容やセリフの区切りの良さを判定しません。

ダイヤルは0000から1234へ操作し、途中の値も正解と重ならないか収録前に検査します。
「調べる」・解答送信・箱の開封・救出は操作しません。
ただし未編集の収録には長い導入や箱の説明が含まれます。公開前に必ずネタバレを点検してください。

## 3. カットと字幕を決めて書き出す

`plan.example.json` をコピーして編集します。パスは**そのJSONからの相対パス**です。
例の秒数は以前の収録から採った出発点で、毎回の発話・操作時刻には一致しません。
**サンプルをそのまま公開用の編集として使わず、今回のsynced.mp4を再生して調整**してください。

```sh
python tools/trailer/trailer.py render tools/trailer/plan.example.json --out .trailer/render --font /path/to/font.ttf
```

主な設定：

|設定|意味|
|---|---|
|source|同期検査に通ったsynced.mp4|
|scenes[].start / duration|素材内の開始秒 / カットの長さ。合計20〜30秒|
|scenes[].inputDuration|任意。映像をこの秒数で止め、末尾フレームをdurationまで保持。保持部分の収録音は無音|
|scenes[].crop|元映像での `[幅, 高さ, 左, 上]`。比率を保って画面内に配置|
|scenes[].zoom|1〜2倍。0.7秒から2秒かけて滑らかに拡大|
|scenes[].caption|短い一文。64px、半透明の暗い背景に明るい文字|
|scenes[].mute|このカットの収録音を消す。説明の途中を切る箱選択の場面などで使用|
|scenes[].closing|原画・タイトル・プレイ案内の終了画面を表示|
|background / artwork|終了画面に使う既存の森 / スノードーム画像|
|music / musicGain|任意の既存BGMと音量。声に合わせて音量を下げる|

字幕は左上の固定位置へ0.3秒のフェードと12pxの上移動で登場し、
3.6秒静止して0.3秒で消えます。発話を聞かせるカットはcaptionを省略できます。
字幕が落ち着く前に主要操作が始まらないよう、カットの開始時刻を選んでください。
クロップ・ズームと字幕で操作部やゲーム内の文字を隠していないか確認します。
字幕が横幅を超える場合は縮小せずエラーにします。

BGMは録音にも含まれるため、追加する場合は元の薄いBGMとの重なりを試聴してください。
0.15はこの曲用の出発点で、別の素材に共通の適正値ではありません。
音割れ検査で失敗したら音量を下げ、新しい出力先で書き出します。

出力は `trailer.mp4`、先頭の `thumbnail.png`、字幕が出た後の `preview.png`、
編集設定のコピー、`render-check.json` と中間ファイルです。
素材の記録 `NOTICE.md` と、動画説明欄などに引き継ぐための `credits.txt` も保存します。
収録・同期・編集とも既存の成果物を上書きしません。
`.trailer/` 以下はGitから除外し、Pagesの配信対象にも追加していません。

## 公開前の確認

全編をデコードして長さと音声ピークを検査しますが、最終的には動画を再生し、
声の自然な切れ目、BGMの聞こえ方、字幕・ダイヤルの可読性、ネタバレを確認してください。
スマートフォンでの視聴や、人が聞いた音質を自動検査の成功だけで保証するものではありません。
字幕の文や演出はゲーム本来の機能と区別できるようにしてください。
投稿・YouTubeへのアップロードは行いません。
