# Gemini音声の制作・検証（2026-10-05）

ユーザーの「Gemini TTSためしていいよ」を受け、既存のGeminiキーで制作した。サブエージェント、公開・デプロイ、新しい契約、課金設定の変更はない。通常のゲーム起動では外部APIを呼ばない。

## 制作した音声

モデル `gemini-3.8-flash-tts`。サンタはAlgieba、語り手はSulafat。穏やかで少しゆっくり、台詞の語句を変えず、謎の解釈や答えを追加しないよう指定した。生成の仕様は [Googleの音声生成資料](https://ai.google.dev/gemini-api/docs/speech-generation) を確認。

九ファイル、合計184.60秒、8,915,376バイト。WAV / 24kHz / 16bit / モノラル。受信したWAVを保存し、C2PAの出所情報も保持。生成入力、声の指定、使用トークン、SHA-256を非配信の `reference/audio-generation/` に記録した。

0000以外の誤答は収録していない。原作の反応にはプレイヤーの入力数字が含まれるため、その数字をブラウザ読み上げで補う。誤答の文言を変えて収録範囲を広げる変更はしていない。

## 実ブラウザで確認

Codex In-app Browser / Chromiumで、開始から正解、読み返しまで実際に操作した。

- 導入・箱の説明・調査1〜4・誤答0000・正解の各画面で、対応するローカルWAVが再生状態になり、長さが取得できることを確認。導入32.4秒と調査2の14.56秒は自然終了も確認した。
- 停止とミュートで音声が停止し、再生位置が0へ戻る。聞き直しの連打後も音声要素は一つで、再生が重ならない。画面変更で旧音声を停止し、別ファイルへ切り替わる。
- ミュート・調査4を保存した状態で再読み込みし、再開後も保持。オンに戻すだけで勝手に流さず、回答／聞き直しで再生する。
- 0000と1111の不正解では箱が閉じたまま。1111の反応で0000の録音は停止し、表示も入力数字1111になる。全角・空白の正解で箱が開き、対応する正解音声が再生される。
- 読み返しでも導入と箱の説明の同じWAVを再利用。390×844のスマホ幅でも再生・ページ送り・停止が動き、横はみ出しはない（clientWidth / scrollWidthとも375px）。これは実機スマートフォンの検証ではない。
- リセットで表紙へ戻り、音声オン・開始待ちとなる。検証用の画面サイズ指定を解除し、ブラウザを残した。警告／エラーログは0件。

音声の長さがInfinityになる問題を発見し、ローカル配信へContent-Lengthと音声のRange対応を追加。HEADの長さ、44バイトの部分取得（206）、範囲外の拒否（416）も確認した。

## 自動・ローカル検査

- `npm test`: 10項目成功。原作台詞との一致、正解のみの開箱、保存／リセット、重複防止、古い音声イベントの無視、ファイル失敗時のフォールバック、登録音声の実在と生成入力を確認。
- `node scripts/verify-audio.mjs`: 九WAVの音声データをローカル検査。ピークは-1.1〜-1.9dB、RMSは-14.8〜-19.4dB、クリップしたサンプルは0。結果は `reference/audio-generation/wave-check.json`。
- 生成・配信スクリプトの構文と `git diff --check` に問題なし。

## 費用と未確認事項

生成入力は原作との照合済みだが、生成音声の全編聴取による読み落とし・誤読・話者の自然さは未確認。追加の自動書き起こしAPIによる検証は、原作由来の生成音声の再送がTTS生成の許可範囲外だとして自動承認レビューに拒否された。その外部送信は実行せず、ローカル検査とブラウザ再生へ切り替えた。検査スクリプトにも外部書き起こし機能を残していない。

実機iPhone/Android、Safariの再生、スピーカーやイヤホンでの聞こえ方、繰り返し読みたくなる価値は未検証。音声が使えない場合は文字で最後まで遊べる。未収録の誤答の声は端末の音声に依存する。
