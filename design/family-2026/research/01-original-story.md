## 0. 要点（先に結論）

1. **物語の核は「忙しい大人（サンタ）にかまってもらえなかった寂しい子（まほう使い）が、"だいすきだよ"と言ってもらい、一緒に遊んでもらうことで満たされる」話。** 【事実】救出条件は「正解」ではなく「遊ぶこと」（`design/FULL-GAME-DESIGN.md:21`、`design/full-game-spec.json:43`）。誤答でも救出される仕様は、原作への忠実さのためだけにあるのではない。テーマを支える構造になっている。
2. **「親子で遊びたくなるアプリ」という今回の目標と、原作のテーマはそのまま一致する。** 結末でまほう使いが言う「だって、だって、さびしかったんだもの。けど、今日はきみと遊べて、とっても楽しかったよ！」（`prototype/full-scenario.js:33`）は、子どもが親に言ってほしいこと／言いたいことそのもの。
3. **原作はスマートスピーカー（リビングにある共有の端末）で、声で遊ぶ前提だった。** そのため文字が読めない子も参加でき、「だいすきだよ」を家族の前で声に出すという儀式が自然に起きていた【推定】。ブラウザ版の2種はどちらも、この合言葉を**文字入力**にしている（`illustrated-prototype/letters/word-math.js:13`、`prototype/full-game.js`）。最も感情が動くはずの場面が、フォームの送信になっている。
4. **原作では誰も「だいすきだよ」を言い返さない。** サンタはまほう使いに謝らない（「まほう使いめ。かまってやらなかったからって、とじこめることはないじゃろう」）。まほう使いの寂しさは結末の1行で初めて明かされ、それまでに伏線がない。ここが最も活かしきれていない点。
5. **謎の難しさは中盤の箱、とくに黄色が山で、後半は下り坂。** 赤（たぬき暗号）と黄（負けるが勝ち＋指の数）は大人も楽しめる本物の謎。青は「調べる」を押すと数字を写すだけの作業になる。後半の三問は正誤を問わず進むクールダウン。
6. **台詞は合計2,475字、語りの音声は約9.3分**（WAV実測560.2秒）。内訳は語り手62%・サンタ16%・まほう使い22%。**サンタは導入の約2分の後、救出まで約20分のあいだ声を出さない。** 家族で遊ぶと全体で17〜33分（中央値約25分）と推定【推定】。
7. **文字を読めることを前提にすると、遊べる最低年齢が1〜2歳上がる。** 声の原作なら5〜6歳でも耳で参加できた謎が、無音の絵本版（PR #1）では、カタカナと小2〜3の漢字を読めないと一人で進めない【推定】。絵本版では大人が読み聞かせることが前提になる。これは弱点にも、共同プレイを生む仕掛けにもなる。
8. **オーナーはこれまで「原作忠実」を一貫して求めてきた**（台詞は誤字まで維持、新しいヒントなし、敵なし、8848の維持、直行経路など25項目以上。§5）。一方で今回の依頼は「現在の実装に縛られる必要はありません」。**この「縛られない」が実装だけを指すのか、物語・謎の改変まで含むのかは、最初に確認すべき【要判断】。**

### 3.2 赤い箱：たぬき暗号（3138）

**手がかりの順番**【事実】（`scenario.js:17-20`）
1. 「箱にはカギがかかっています。ダイヤル式のカギです。開けるためには四つの数字が必要です。何か書いてあるようです。」
2. 「箱には「サンタ、イタチ、サンタ、ハタチ」と書いてあります。絵もかいてあるようです。」
3. 「…その横にたぬきの絵がかいてあります。絵の下にも何か書いてあるようです。」
4. 「絵の下に「たぬき」と書いてあるのですが、最初の「た」の文字のところにバツが書いてあります。この箱は調べつくしたようです。」

**解き方**：たぬき＝「た」を抜く。サン**タ**→サン=3、イ**タ**チ→イチ=1、サン**タ**→3、ハ**タ**チ→ハチ=8 → **3138**。
**原作の変化形**【事実】：4候補（3138/3183/3813/3831）。先頭はいつもサンタ（`full-game-spec.json:7-12`）。現行は3138に固定。
**正解すると**：「す」「だ」（スイカの「す」、大根の「だ」）。
**ヒント**：単独のヒント台詞はない。調べる段階を進めることがヒントになり、4段階目がほぼ答え（`SOURCE-NOTES.md:27`）。
**分析**【推定】
- たぬき暗号は日本の幼児・低学年向けなぞなぞ本の定番。親も子どもの頃に解いた記憶があり、「懐かしい」と感じる共通体験になる。
- **サンタ自身の名前が鍵の一部**（サン＝3）になっている遊び心。
- 「ハタチ」（20歳）を知らない子もいるが、解くのに意味は不要。大人は一瞬「20？」と迷う可能性がある。
- **声の原作では耳で聞くだけで済んだ**。文字版ではカタカナを読む必要があり、5〜6歳には壁になる。PR #1は「サンタ、イタチ」「サンタ、ハタチ」の2行で表示している（`illustrated-prototype/red-box/inspection.js:15-17`）。
- 大人と一緒なら：大人が「たぬきって、"た"を抜くってこと？」と問いかけ、子どもが声に出して「サン…イチ…」と言う。役割を分けやすい。

### 3.3 青い箱：サガルマータ（8848）

**手がかり**【事実】（`full-scenario.js:20-23,28`）
1. 「…開けるためには四つの数字が必要です。絵がかいてあるようです。」
2. 「箱には山の絵がかいてあります。絵の横にも何か書いてあります。」
3. 「…その横に「サガルマータ」と書いてあります。まだ何か書いてあるようです。」
4. 「よく見ると、さらにこう書いてあります。「その高さは、この端末が知っている」。箱は調べつくしたようです。数字を合わせますか？別の箱を調べますか？サガルマータについて調べますか？」
- 情報（調べると出る）：「サガルマータは、ネパール語で、エベレストのことです。エベレストは、世界で一番高い山です。エベレストの高さは、8848メートルです。」

**正解すると**：「い」「よ」（イルカ、ヨーグルト）。

**声のアシスタントに依存していた点**【事実＋推定】：「**この端末が知っている**」は、いま話している相手（Googleアシスタント）に聞けばよい、というメタな手がかり。原作には `sagarmatha` の応答があった（`FULL-GAME-DESIGN.md:171`）。ブラウザではこの仕掛けが「ボタンを押すと資料が開く」になり、気の利いた点が消える。

**8848問題**【事実】：現在の公式値は8848.86m（`FULL-GAME-DESIGN.md:170,180`。ネパール観光局2024年資料）。現行は「※この謎では、原作時点の高さを使います。」と表示している（`illustrated-prototype/blue-box/box-math.js:15`）。【推定】家族がスマホで検索すると8849や8848.86が出てきて、子どもの前で矛盾する。逆に「本当はいくつ？」を親子で調べる学びのきっかけにもなる。

**分析**【推定】：謎というより「調べ方を知る」問題。大人が答えを知っていると一瞬で終わる。**家族向けには「その高さは、おとなが知っている」のように、大人を"端末"の代わりにする**読み替えができる。ただし原作の文言を変えることになるので【要判断】。

### 3.4 黄色い箱：負けるが勝ち＋指の数（2502）

**手がかり**【事実】（`full-scenario.js:24-27`）
1. 「…絵がかいてあるようです。」
2. 「箱にはじゃんけんのグー、チョキ、パーが全部で4つかいてあります。かいてあるのは「グー、チョキ、パー、グー」です。絵の横に何か書いてあります。」
3. 「…その横に「負けるが勝ち」と書いてあります。まだ何か書いてあるようです。」
4. 「よく見ると「指の数があなたをみちびく」と書いてあります。この箱は調べつくしたようです。」

**解き方**：それぞれの手に**負ける**手を出す。グーに負けるのはチョキ（指2）、チョキに負けるのはパー（5）、パーに負けるのはグー（0）→ グー・チョキ・パー・グー ＝ **2・5・0・2**。
**原作の変化形**【事実】：異なる3つの手の順列6通り×最後の手3通り＝18候補。そのうち6つは0で始まる（`full-game-spec.json:14`、`check-flow.mjs`）。
**隠れたヒント**【事実】：調査4段階目のあとに間違えると、**画面にだけ**「負けるが勝ちなので、グーに勝つのはチョキのようです。」と出る（音声には含まれない。`full-scenario.js:60`、`FULL-GAME-NOTES.md:58`）。「赤と黄に単独のヒントはない」とされているが、実際にはここが例外になっている。
**正解すると**：「き」「だ」（キリン、大根）。

**分析**【推定】
- **0250の罠**：描かれた手そのものの指を数える（グー0・チョキ2・パー5・グー0）と0250になる。最初に試しそうな答えで、大人も引っかかり得る。「指の数が**あなた**をみちびく」の「あなた」＝自分が出す手、と読めれば正解に届く。言葉の選び方が丁寧な謎。
- **体を動かせる唯一の謎**。親子で実際に「負けじゃんけん」をしながら解ける。逆にするのは子どもにも大人にも意外と難しく、盛り上がる。
- 原作のバンクには0で始まる答えもある。数値として扱わないこと（`FULL-GAME-DESIGN.md:62`）。
- PR #1では、絵を見て一手ずつ選ぶラフが別にあり、正誤や数字への変換は補助しない（`INTERACTION-GUIDANCE.md:21-29`）。

### 3.5 六文字→「だいすきだよ」

**手がかり**【事実】：赤「す・だ」、青「い・よ」、黄「き・だ」。それぞれ絵の単語が添えてある（スイカ、大根、イルカ、ヨーグルト、キリン、大根）（`full-scenario.js:29`、`illustrated-prototype/letters/word-math.js:2-8`）。「だ」の2枚は別の紙として扱う（`full-game-spec.json:36`）。
**受理する表記**：原作 `witch_usersays_ja.json` の「ダイスキダヨ」「だいすきだよ」「大好きだよ」（`full-game-spec.json:16`）。PR #1は `['だいすきだよ','大好きだよ']` を正規化して比べ、カタカナはひらがなに変換する（`letters/word-math.js:13,27-30`）。
**直行経路**【事実】：合言葉を知っていれば、箱を開けずにまほう使いを呼べる（`FULL-GAME-DESIGN.md:45`）。【推定】もとは「今は遊ばない」で会話が終わった後、次回に合言葉で直接呼び戻すための入口（`full-scenario.js:31`「あそびたくなったら、ひみつの言葉で私をよんでね」）。
**分析**【推定】：謎としては易しい。「だいすき」が見えれば一瞬で、大人は文字を見た瞬間に分かってしまい、**先に言ってしまう危険がある**。絵の単語があるので、文字が読めない子も絵カードとして参加できる。この謎の本当の価値は難しさではない。**正解を口にすること自体**にある（§4）。

### 4.1 曲線（正解ルート・家族プレイ約25分を想定）

```

   |  ★救難              開箱 開箱  開箱      /    \登場(笑)    /    \クリスマスの夜へ

    サンタの声 ......(サンタは黙っている：約20分)....................... サンタ再登場
```

【推定】
- **緊張の山は箱（とくに黄）、感情の山は合言葉と結末**。その間の三問は、楽しくて失敗のない時間になっている。
- 動機（寂しさ）の種明かしは**最後の5%**で、一言だけ。断る分岐（8b）を選んだ人だけが先に「せっかくあそぶ相手が見つかったと思ったのに」を聞く。正解ルートの大多数には伏線がない。

### 4.2 テーマ：「だいすきだよ」は誰が誰に言うのか

**原作での構造**【事実＋推定】
- まほう使いが残した箱の答えは「だいすきだよ」。サンタは「この端末によびかけてくれれば、わしはここから出ることができる」（`scenario.js:14`）とだけ言い、それが**まほう使いへの「大好き」**だとは知らない（ように描かれている）。
- 呼ばれたまほう使いは「**あなたが大好きな**、まほう使いが来ましたよー！」と言い、続けて「あれれ？あなた、だれ？」「**サンタじゃなくて**、あなたが私をよんだのね」。【推定】**まほう使いは、サンタに「だいすきだよ」と言わせるための鍵を作っていた。** 閉じ込めは、かまってもらえない子が「大好きと言ってくれたら出してあげる」と仕掛けた、寂しさの裏返しになっている。
- 実際に言ったのはプレイヤー（子ども、または家族）。まほう使いはがっかりせず、「ふーん。まあ、いいわ」と新しい遊び相手を受け入れる。**「大好き」を言ってくれた見知らぬ子と遊ぶことで満たされる。**

**親子の場面として強い理由**【推定】
1. **役の対応がはっきりしている**：サンタ＝12月に忙しい大人（「プレゼントのじゅんび」はまさに親の師走）。まほう使い＝かまってもらえずにいたずらする子。プレイヤー（親子のチーム）＝そのあいだを取り持つ人。子どもはまほう使いに、親はサンタに自分を重ねやすい。
2. **ゲームが「言う口実」になる**：日本の親、とくに父親は子どもに面と向かって「大好きだよ」と言いにくいことが多い。年齢が上がると子どもも言わなくなる。「合言葉だから」という遊びの枠があると、照れずに口に出せる。
3. **答えが「一緒に遊ぶ」**：救出の条件が「正解」ではなく「遊ぶこと」。アプリの教訓とアプリの使われ方（親子で遊ぶ）が同じ形をしている。
4. **敵がいない**：悪役は「寂しかった子」。罰ではなく理解と遊びで解決する（`FULL-GAME-DESIGN.md:21`、`PLAN.md:38`）。

## 6. プレイ時間とペース

### 6.1 区間ごと

語りの秒数は `prototype/assets/audio/*.wav` を `afinfo` で実測した【事実】。考える時間・操作は【推定】（観察データなし）。

### 6.2 ペースの観察【推定】

1. **前半が長く、後半が短い**：箱の区間が全体の約6割（10〜19分）。物語の山（合言葉・登場・結末）は後半の約7分に集中している。
2. **主人公が長く黙る**：サンタの声は約2分の時点で消え、約23〜25分で戻る。まほう使いは残り約25%にしか出てこない。中盤は語り手（端末）の定型文が続く。
3. **難しさの山（黄）が感情の山（合言葉）の直前に来ることがある**：自由順なので、黄を最後に回した家族は、一番難しい謎の直後に一番感動的な場面へ入る。疲れて流してしまう危険がある。
4. **区切りどころがある**：「今は遊ばない」（8b）は物語上の自然なしおり。25分を一度に遊べない家庭（寝る前15分など）でも、2回に分けて遊べる構造がもともとある。
5. **25分という長さ**は、週末の親子時間や寝る前の読み聞かせ（15〜20分）の枠に、ほぼ収まるか少しはみ出す。

## 7. 家族向け製品の設計に向けた論点（決定はしない）

【要判断】として、オーナーに最初に確認すべき順に並べた。

1. **「縛られない」の範囲**：実装（UI、技術、絵）だけか。台詞の追加（U2・U4・U7）、遊びの追加（U5）、謎の差し替え（C5・C14）まで含むか。C13・C26との関係。
2. **合言葉の儀式**：「だいすきだよ」を声に出す体験を、マイクなしでどう取り戻すか（自己申告／声をそろえる演出／端末内の認識）。誰が誰に言うのか（子→まほう使い、子⇄親、全員で）。
3. **言い返しと仲直り**：結末で「だいすき」を返す場面を足すか。サンタがまほう使いに一言かけるか。原作の台詞は残したまま、足すだけにするか。
4. **大人の役割の設計**：大人を「ヒントを持つ人」「読み聞かせる人」「サンタの声をあてる人」「答えを知っている端末」のどれにするか。C6（ヒントなし）を大人専用のヒントで緩めるか。
5. **年齢帯**：主な対象を4〜6歳（大人が読み聞かせる前提）にするか、7〜9歳（ほぼ自力）にするか。この選択で、赤・青・黄の見せ方、音声が必須かどうかが決まる。
6. **8848か8849か**：原作時点の値を明記して維持するか、現在の値に更新するか、大人が答える形へ読み替えるか。
7. **再プレイ**：原作の問題バンク（432通り）を戻すか。年ごと・きょうだいごとに違う問題にするか。
8. **現実のクリスマスとの接続**：11週間後のイブにつなげるか（例：イブ限定の最後のページ）。続編を作らない制約（C12）とどう両立させるか。
