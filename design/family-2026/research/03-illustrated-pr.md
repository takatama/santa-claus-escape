## 0. 要点（TL;DR）

1. **物語と謎は親子向けの素材として非常に良いが、PRでは「声と体を使う遊び」が「読む・打つ・押す」に変わっている。** 秘密の言葉が「だいすきだよ」、魔女の三問は「クリスマスに隠れた生き物（クマ）」「シカを10回言ってからの引っかけ（ソリ）」、黄色い箱は「負けるが勝ちのじゃんけん」。どれも親子が声に出したり手を出したりすると一番盛り上がる題材なのに、PRでは文字入力（IMEが必要）とボタンで処理されている（`witch/conversation.js:31-43`, `letters/word-math.js:13-14`）。
2. **絵の品質は高い。** 深い紺と金の光、羊毛フェルトのような質感のサンタ、スノードーム、手を差し出す少女のまほう使いは、そのまま「キービジュアル」として使える水準。一方で、箱・錠・紙・UIパネルはコードで描いたもので、絵本の画面の上に「Webアプリの部品」が重なって見える。
3. **音はまったく無い。** `Audio`/`speechSynthesis`/音声ファイルの参照は0件。ただし `main` の `prototype/assets/audio/` には同じ原文のTTS音声・BGM・効果音が103ファイル（77MB）ある（例：`intro.wav`, `ja-leda-question-deer-ten-times.wav`, `dial.mp3`, `unlocking-1.mp3`）。会話モデルにも `spoken`／`bgm` という使われていない受け口がある（`witch/conversation.js:41,130,140`）。
4. **ゲームの進め方は「大人が読み上げ、子どもがタップする」形に自然となる。** ただ、そうなるように作られているわけではない。漢字はユニーク121字でふりがな無し、本筋の台詞だけで約1,050字ある。8〜12pxの文字指定がCSSに63箇所ある。
5. **見つけやすさに具体的な欠陥がある。**
   - 森の画面で最も目立つ金色のボタンは、開始直後から「ひみつの言葉を伝える」（`explore/index.html:46`）。
   - 「最初から」は確認なしで全部の進行を消す（`explore/main.js:81-85`）。
   - 1280×720では、導入と魔女の誘いの次へ進むボタンが画面の外にある（QA画像で確認）。
6. **見た目・手触りの反応（ジュース）に偏りがある。** 雪払い（約5秒の払う動き＋雪片）、ふた、枝、救出は丁寧に作られている。一方で、解錠の失敗・成功、紙の取得、「だいすきだよ」の成功は文字が出るだけか、ボタンが無効表示になるだけ。成功した紙カードは灰色になって終わる（`letters/main.js:103,114`）。
7. **作りは「検証用試作として非常に堅牢、製品の土台としては作り直しが必要」。**
   - 状態は検証付きの純関数（`journey/state.js`）、保存は世代番号と更新番号つき（`journey/store.js`）、テストは101組。このロジックの部分は残す価値がある。
   - 一方でページは9つに分かれていて、遷移のたびに全部読み込み直す。1画面あたり4〜9枚、1.3〜3MBのPNGを読み、JavaScriptで1画素ずつ走査して余白を切り落とす。描画は三角形ごとに切り抜いて `drawImage` する方式で、1フレームあたり最大約1,000回。三箱のコードはほぼ同じものが3回書かれている（3,573行で、実行時JS 6,034行の59%）。
   - BGMをシーンをまたいで流し続けたいなら、ページを分ける構成とは相性が悪い。
8. **PR自身が「未検証」と書いている中核はすべて体験の部分。** スマホ実機の指操作、初めて遊ぶ親子の理解、他のブラウザ、スクリーンリーダー、魅力・解放感がそれにあたる。しかも Cloudflare Pages のビルドに illustrated-prototype が含まれていないため、実機で触れる公開URLが存在しない（`scripts/build-pages.mjs:3-16`、プレビューURLを実際に取得して確認）。

  - 返答 →「続きを見る」→「うふふ。ああ楽しかった！」→ **2秒で救出へ自動遷移**（`witch/main.js:19-35`）。
- **所要時間**：1〜2分
- **大人**：「一緒に10回言おう」と自発的にやれば盛り上がる。答えは大人が入力する。

#### ⑬ 救出 `rescue/index.html`

- **操作と実装【事実】**

  - 球の右側に開口ができ、サンタが歩いて外へ出る（足踏みは近似）。
  - 100%で「サンタのお話を読む ›」が出て、結末256字が表示される（`:26-31`）。
  - **左へ戻すとサンタは球の中へ戻り、結末も隠れる**（`:206-208`）。

- **大人**：結末を読む（「クリスマスの夜を楽しみにしていてくれ」）。

### 3.4 親子の役割として見た評価【推定】

## 4. アートディレクション評価

### 4.1 画風【事実＋評価】

- 背景（`assets/forest-clean.png` 1586×992）

### 4.2 強いところ（具体的に）

1. **スノードームという一つの絵だけで、状況（閉じ込められたサンタ）と願い（出してあげたい）が伝わる。** 子どもにとっても大人にとっても、説明の要らない「アイコン」になっている。ストアの画像やSNS向けにそのまま使える【推定】。
2. **発見の演出**：根元を固定したまま枝の網目が変形し、奥の光とまほう使いが照らされる（`main.js:110-138,188-198`）。板を回転させたり出現を切り替えたりせず、「かき分けると見えてくる」という絵本の身体感覚を再現している。逆にも動かせる。
3. **雪払い**：曲線に沿った消去の跡と雪片で、「手で払っている」感じが出ている（`red-box/inspection.js:256-285`）。払った後も行間に雪が残る質感は丁寧。

6. **たぬきの絵**（`red-box/assets/tanuki.png`）は可愛く、手がかりとしての読みやすさと情緒を両立している。

1. **コードで描いた部品と絵の質感に差がある。**

### 5.2 状態と保存【事実＋評価】

- 状態の形は `journey/state.js:17-30` のとおり：`{version:1, introduction, introductionRevision, boxes{red,blue,yellow:{unlocked,progress,collected,code,snowStage}}, letters{slots[6],draft,called}, discovery{progress,met}, conversation{phase,questionIndex,draft,responses[],reinvited}, conversationRevision}`

  - localStorage の専用キー `santa-illustrated-journey-v1` に、`{generation, state}` の形で入れる。
  - 「最初から」で新しい世代（UUID）を作る（`:24-26,73-81`）。古いタブからの保存は世代が合わないので無視される（`:57-71`）。

  - ただし「複数タブで同時に操作されたときの競合」まで守る工数は、家庭向けとしては過剰。

    - クリアの記録（思い出・証明書）がない。

### 5.3 描画【事実＋推定】

- 各ページが独立した Canvas 2D で、DPRの上限は2。毎フレーム、背景を `cover` で描き、その上に部品を重ねる。
- **網目変形**（`rescue/paint.js:30-61` と `main.js:141-180` が同じ実装）
  - 三角形ごとに `save → clip → transform → drawImage(画像全体) → restore` を行う。
  - 1フレームあたりの回数：
    - 発見：枝 2×(9×12×2)=432回、球 12×14×2=336回 → **約770回**
    - 救出：枝432＋魔女240＋サンタ384 → **約1,056回**
    - 赤箱：枝432＋ふた84＋ふたの雪84＋球336 → 約936回
  - 救出では毎フレーム `plate.width = …` で 1312×1199 のキャンバスを作り直している（`rescue/main.js:101`）。
  - 低価格のタブレットや古いiPhoneで60fpsを保てるかは【未検証】。WebGL（PixiJSなど）なら同じ表現をGPUで軽く描ける【推定】。
- **画像の読み込み**
  - 透明な余白を、実行のたびにJSで全画素を走査して切り落としている（`rescue/paint.js:1-20`。`main.js:37-63` も同じ）。約1.5M画素の画像を、ページごとに4〜9枚。

  - **1ページの初回読み込み量**：
    - intro と explore：約19.4MB（intro は箱を表示しないのに、箱6枚を読み込む。`intro/main.js:27` → `explore/scene.js:106-111`）

  - 実行時の画像を合計すると約33MB（重複なし）。
  - 画面表示に合わせた WebP/AVIF にすれば、1/5〜1/10になる見込み【推定】。
  - 画像を展開した後のメモリは、explore で約60MB以上＋切り落とし用の複製【推定】。iOS Safari のキャンバスメモリ上限に注意が必要。

## 8. 設計への示唆（統合レポート向けの材料）

### 8.1 必ず残す資産

### 8.2 変えるべき前提

1. **「読む・打つ」から「聞く・言う・手を出す」へ。** 問1と問3は声で答える（大人が「当たり！」を押す、または音声認識）。「だいすきだよ」は二人で声に出す儀式にする。じゃんけんは実際に手を出す。
2. **大人の役割を作品が明示的に設計する。** 読み手、ヒント係、判定係。例：大人だけが見るヒントや答え。最初に「大人は読み聞かせ係」と伝える。
3. **ページ分割から単一ページへ**（BGMと読み上げを途切れさせない）。素材の軽量化と事前切り抜き。
4. **山場の「祝い」を作る。** 紙が飛んでくる、鈴の音、魔女の表情差分、救出後の記念画面。
5. **誤操作への防御**（やり直しの確認、救出後は固定）とセーブ枠。
