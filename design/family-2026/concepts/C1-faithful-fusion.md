## 1. 名前・キャッチコピー・約束

- **名前**：サンタの脱出 ―「声と絵の動く絵本」（作業名 C1）
- **キャッチコピー**：「物語は一字も変えずに。おうちの人の声と子どもの指で、ひと晩でひらく絵本。」
- **約束（3行）**
  1. 原作の台詞・謎・答え・順番は一字も変えない。足すのは「読み方」「触り方」「声に出す合図」の3つだけ。
  2. 一晩25〜45分で最後まで遊べる。途中でやめたくなったら、原作の「今は遊ばない」がそのまましおりになる。
  3. 広告・課金・アカウント・マイク・実行時AI・解析はなし。一度開けばオフラインでも動く。

## 2. 誰が・いつ・どこで・何分・どの端末で

- **中心**：5〜7歳の子＋おうちの人1〜2人（ブリーフ §7.1 の設計帯）。3〜4歳は膝の上、8〜9歳は自分で読む役。
- **いつ**：夕食後のリビング（寝る直前ではない。07 P22）。11/29〜12/23 のどこか一晩。山場の週末は 12/19〜20。
- **端末**：①共用タブレットを横置き（第一）②親のスマホを横持ち（第二）③テレビは OS の画面ミラーリング（案内だけ）。スマホ縦持ちでも遊べるが、絵が小さくなる（§9）。
- **何分**：通しで25〜45分【推定】（03 の推定と 11 の実プレイが一致）。前半「三つの箱」20〜35分、後半「まほう使いと遊ぶ」8〜12分。

**家族A（週末の一晩・タブレット）**【想定】
- 首都圏のマンション。父39歳（平日の帰りは21時過ぎ）、母37歳、ゆいちゃん6歳（年長）、そうたくん3歳。
- 12/19（土）19:00、夕食後。リビングのローテーブルで、共用の iPad（第9世代）を横置きスタンドに立てる。
- 語りは「モードB」：父が「端末」の語りを読み、サンタとまほう使いは録音の声。
- 役割：ゆいちゃんは雪をこすり、ダイヤルを回す。そうたくんは父の膝の上で、ふたを持ち上げる係とシカの合唱。

**家族B（平日の夜・スマホ）**【想定】

- 経過：母は片付けの後、赤い箱の途中から参加する。黄色の箱では母が 0250 に引っかかり、はるとくんが「負けるんだよ！」と正す。シカ10回は二人で声をそろえる。

**大人が「見守る人」ではなく「楽しむ参加者」になる理由**【推定】
1. **役がある**：原作の語り手は端末そのものの一人称「私」（`prototype/scenario.js:9`）。モードBでは、大人がその「私」を演じる。語りは台詞全体の62%を占める（01 §2.1）。大人は物語の中の人物になり、ただの代読係ではなくなる（08 §3.9 の Little Orpheus 型）。
2. **大人も引っかかる謎がある**：0250 の罠、「ハタチ？」、たぬき暗号の懐かしさ。どれも原作にもともとある（01 §3）。
3. **声が要る儀式が3つある**：だいすきだよ、シカ10回、答えを口で言う。大人の声がないと成り立たない。
4. **二重の物語**：「忙しいサンタと、かまってほしかった子」の構図は、大人に別の意味で届く。C1 は説明を足さず、原作の結末の一行に任せる。
5. **操作の説明係にしない**：開発者向けの案内、スライダー、小さなリンクを子どもの画面から外す。大人の話す内容を「操作の説明」から「物語」へ移す（Munzer 2019、P2）。

## 5. 4つの山場

### ①「だいすきだよ」― 声で呼ぶ
- **流れ**：
  1. 紙を正しく並べると、六枚が灰色にならずに**金色に灯る**（PR #1 の灰色表示と1.1秒の自動遷移はやめる）。
  2. 絵記号（二人の顔と声の線）と「こえに だして よんでみよう」が出る。主操作は「『だいすきだよ』と よぶ」。
  3. 押すと、だ・い・す・き・だ・よ が1字ずつ約0.35秒おきに灯る（カラオケの合図）。家族はそれに合わせて声をそろえる。
  4. 灯り終えると登場音が鳴り、森の奥が光る。
- **原作との関係**：原作は「この端末によびかけてくれれば」（`scenario.js:14`）。声で呼ぶ行為を、マイクを使わずに取り戻す。判定は「並べ方の完全一致」のまま。言ったかどうかは機械では判定しない（P9）。並びが違うときは何も起きない（`prototype/full-game.js:59`、ブザーなし）。
- **大人の楽しみ**：「合言葉だから」という遊びの枠があるので、照れずに言える（01 §4.2）。演出メモには「言ったあと、お子さんに言い返すのもおすすめ」とだけ書く。**台詞は足さない。言い返すかどうかは家族に任せる。**
- **しおりで二度目が来る**：13' で本を閉じると、次に開いたとき「ひみつの言葉で私をよんでね」に従って、家族はもう一度「だいすきだよ」を言う（原作の再訪の経路、`full-scenario.js:31`）。**二晩に分けると、合言葉を二度言うことになる。**
- **測り方**：言い合いが起きた組の割合（目標80%以上）。大人が事後に「印象に残った場面」に挙げたか。

### ② シカ10回 ― 一緒に声をそろえる
- **素材**【事実】：PR #1 は字幕「シカ、シカ...」だけで、10回分の `spoken` を使っていない（`witch/conversation.js:40-41`）。一方 `prototype/` の Leda の音声は、シカを10回言う版を録ってある（`ja-leda-question-deer-ten-times.wav`、21.5秒）。
- **流れ**：
  1. まほう使いが「わたしといっしょに…」と言う。
  2. 画面の雪の上に鹿の足跡が10個並び、Leda の「シカ」1回ごとに1つ灯る。録音の発話時刻を手で拾った10点の時刻表に合わせる。
  3. 家族が声をそろえる。
  4. 「では問題。サンタが乗ってくるのは？」の後は、口で答えてから「こたえを いったよ」を押す。
  5. 「なんて こたえた？」の絵札（ソリ／トナカイ／ほかの こたえ）を選ぶ。
  6. 正誤に合わせた原作の返答（`…deer-ten-times-right/wrong.wav`）が鳴る。
- **なぜ絵札は答えの後か**：先に「ソリ」を見せるとひっかけが崩れる。子どもが自分で「トナカイ」を選ぶと、「トナカイ、じゃなくて、ソリだよね」がそのまま返事として成り立つ。
- **大人の楽しみ**：子どもが引っかかる瞬間を目の前で見られる（07 §3.1 d）。大人が引っかかってもよい。
- **測り方**：声をそろえた人数。「トナカイ」と答えた割合。笑いの回数。

### ③ 救出 ― 子どもの手で光をほどく
- **流れ**（原作の順番 `prototype/timed-audio.js` のとおり。子どもの操作で一度だけ止める）：
  1. 問3の答えの後に、まほう使いが「うふふ。ああ楽しかった！」と言う。
  2. 球のまわりに金色の糸が現れ、「ひかりを ほどこう」の絵記号が出る。
  3. 子どもが右へ引く（タップなら20%ずつ）。
  4. 100%に達すると救出音（shine3）が鳴り、語り「シャララララーン。端末の中からサンタがあらわれました。」。モードBでは大人が「シャララララーン」を読む。
  5. サンタが歩いて外へ出る（PR #1 のアニメーション）。
  6. 会話（37.4秒）→ 1秒 → 結び。BGM は Laid_Back に戻る。
- **変更点**：PR #1 では左へ戻すとサンタが球に戻り、結末も隠れる（`rescue/main.js:206-208`）。C1 では、99%までは戻せて100%で確定する【要判断】。
- **大人の楽しみ**：「だって、だって、さびしかったんだもの。」で、子どもはまほう使いに、親はサンタに自分を重ねやすい【推定】。C1 は解説を足さない。
- **測り方**：救出の場面で大人と子どもが画面を見ていたか。大人が事後にテーマを自分の言葉で言えたか。

### ④ 現実のクリスマスとの接続 ― 新しい中身は足さず、「本棚に残す」
C1 は新しい台詞もエピローグも作らない。原作の結末「クリスマスの夜を楽しみにしていてくれ」を最後の声にし、次の3つを置く。
1. **読み返し**：遊んだ経路を、声つきの絵本として再生する（L7。`FULL-GAME-DESIGN.md:182-186` の方針）。約10分【推定】。「おとなのかたへ」に「24日の夜、ねる前に読み返すのもおすすめです」と1行だけ書く。**通知はしない。**
2. **ひみつの言葉で よぶ**：遊び終えた後も、表紙から合言葉でまほう使いを呼べる。三つの遊び＋救出を約8分でもう一度遊べる（原作の直行経路。紙や開箱は作り出さない）。24日の夜の「アンコール」として使える。
3. **六枚の紙の印刷シート（任意）**：す・だ・い・よ・き・だ の紙を A4 に印刷できる（名前は入れない）。ツリーや靴下のそばに置ける。
- **正直な限界**：大人が自分で思い出さないと、24日にはつながらない。現実へ橋をかける力は、日付や印刷物で仕掛ける案より弱い（§12）。

## 7. 年齢・読み・詰まりへの対処

**年齢**
- **5〜7歳（中心）**：モードB＋ふりがな。手の操作（雪・錠・ふた・紙・枝・光）は全部子ども。謎は大人と一緒に解く。
- **3〜4歳**：膝の上で聞く役。ふた、枝、光は引くだけで動く。シカは4歳から一緒に言える（01 §3.1）。謎は解かなくても最後まで進む（後半は正誤を問わない）。
- **8〜9歳**：モードAで自分で読む（ふりがなは切り替えられる）。黄色を自力で解く役。年下のきょうだいがいるときは、**この子が「端末」役（モードB）になって読む**こともできる。
- **きょうだい**：箱を一人一つ受け持つ（「赤はおねえちゃん」）。アプリは担当を強制せず、演出メモで勧めるだけ。儀式（だいすきだよ、シカ）は全員でやる。

**読み**
- 台詞は原文の漢字かなのまま、**すべての漢字にルビ**を付ける（大人メニューで切り替え）。「端末（たんまつ）」も同じ。
- 新しく足す案内文は、ひらがなの分かち書きにする。本文は 20px 以上、子どもに見せる文は 24px 以上。8〜12px の指定（PR #1 で63か所）はなくす。
- **「端末」が通じない問題（W8）**：文は変えない。代わりに、①語り手が話すと画面の縁が灯る（この機械がしゃべっている、と見える）②演出メモ「『この端末』で画面を指さして読む」③サンタの声は球から、の3つで「機械の中にスノードーム、その中にサンタ」と見せる【推定・要検証】。D5 の最終判断はオーナー。
- 文字入力（IME）は本筋から外す。数字は錠、文字は紙と絵札で扱う。

**ヒントと詰まり（新しいヒントは足さない。C8 を守る）**
- 使えるのは原作の仕組みだけ：調べる段階を進める、青の資料、黄の第4段の後の誤答で出る隠しヒント、箱を自由な順で選べること。
- **詰まったときの出口も原作にある**：箱を2つ開けると紙が4枚そろう。そこから合言葉を推理して直行できる（原作の経路）。演出メモには「別の箱から開けても大丈夫」とだけ書く。
- 30秒〜2分操作がなくても、催促の音や表示は出さない（P3）。
- 弱点：黄色で2分以上詰まる組が出るかもしれない【推定】。試遊で多く出たときに限り、「大人だけの問いかけメモ」を別案として出す（A3、C8 の「観察の後に別案」）。

## 9. 技術構成（ブリーフ §8 との整合）

- **配布**：PWA を Cloudflare Pages で静的配信。manifest と自作の Service Worker で約11〜15MB を事前に保存し、オフラインで動かす。ホーム画面への追加を大人メニューで案内する。`build-pages.mjs` は、台帳に載っていて参照されているファイルだけを配信するよう直す。公開はオーナーが行う（C25）。
- **実行時**：素の ES モジュール、依存なし、1ページ（SPA）。9ページ構成と `?journey=1` は捨てる（04 推奨C：PR はマージせず移植）。
- **物語データ**：台詞は `prototype/scenario.js`／`full-scenario.js` から JSON 1か所へ移す。台詞IDと音声クリップの対応、ルビの層、演出メモを別のファイルに分ける。**「ルビを外すと原文と1字も違わない」ことを CI で検査する**（C1 の約束を機械で守る）。
- **状態**：`prototype/full-game.js` の純粋な状態機械（12フェーズ、`revision`）を土台にし、語りモードとしおりを足す。保存は localStorage の小さな状態だけ。区画ごとに寛容に復元し、読めないものは退避する（B1 の反省）。別タブは BroadcastChannel で知らせる。
- **描画**：PR #1 の純関数をそのまま使い、描画の裏側を差し替えられるようにする。まず Canvas 2D（動かない層のキャッシュ、メッシュは4×6分割）で全編を通す。W6 の実機計測で 30fps を割る場面だけ、自作の WebGL2 層へ切り替える（10 の予備案を先に使う、低リスク寄りの順番）。雪のマスクは Canvas 2D、文字とボタンは DOM。
- **音**：AudioContext を1つ使い、表紙のタップで有効にする。`navigator.audioSession.type='playback'`（対応する端末だけ）。台詞はスプライトの AudioBuffer にし、`prototype/timed-audio.js` のタイムライン（世代番号での取り消し）をそのまま使う。`visibilitychange` で再開する。失敗したら字幕で続ける。
- **オーナーの技術制約との関係**：L4 は全部守る。マイクは使わない（`Permissions-Policy: microphone=()` 維持）。サーバーも「無線機」ページも QR も置かない。外部へのデータ送信は0。
- **テスト**：PR #1 のユニットテスト（101件）と `prototype/` の不変条件46件を `node:test` へ移し、CI で必ず実行する。Playwright で次を確かめる。
  - 箱の順番6通り、しおりの経路、直行の経路
  - 3つの画面サイズ（iPad 横、iPhone 縦、1280×720）での見た目の差分
  - オフライン
  - `?test=1` で進行度を固定する

## 12. この案の正直な弱点と、あえてやらないこと

**弱点**【推定】
- 大人の楽しさは、原作にもともとある層（懐かしい謎、二重の物語、語り手の役）に頼っている。大人だけのための新しい中身はない。
- 誰も「だいすきだよ」を言い返さない。サンタも謝らない（W2・W3）。C1 は台詞を足さないので、言い返しは家族の自由に任される。
- まほう使いの寂しさは、結末の一行まで見えない（W4）。サンタは約20分しゃべらない（W5）。青い箱は写すだけのまま（W7）。
- 前半20〜35分は、寝る前の15〜20分に収まらない。章立てはしない。
- 現実のクリスマスへのつながりは「読み返し」と「呼び直し」だけ。日付や家の中の仕掛けを使う案より弱く、市場の空白（§6.5「強い接続×共遊の設計」）を取りきれない。
- スマホを縦に持つと絵が小さい。縦長の絵がない。
- 毎回同じ問題なので、二度目は驚きが減る。

**あえてやらないこと**
- 台詞・謎・答えの変更と追加（言い返し、謝罪、サンタの反応、「端末」の言い換え、誤字の修正）
- 新しいヒント、ヒントボタン、答えを見るボタン
- 夜ごとの章立て、アドベントの日付による解放、通知
- 親のスマホの「無線機」ページ、QR、印刷して家に隠す手がかり探し
- 子どもの名前を入れること、写真や声の録音、マイク、実行時AI、アカウント、解析
- 自作や代わりの効果音（雪の音、鈴の代わり）
- ストア版、英語版、問題バンク（2027年に「原作に戻す」形で検討する）

## 13. 他の案へ移植できる要素

1. **語りモード3種（A 全部声／B 語りは大人＝「端末」役／C 全部大人）**：声の作り方を差し替えられる設計なので、Gemini の規約のリスクにも備えられる。どの案の語りにも使える。
2. **灯る六文字（カラオケの合図）**：一字ずつの光で声をそろえ、マイクなしで「声で呼ぶ」を取り戻す。成功を灰色にしない。
3. **シカの足跡**：録音の10回のシカに足跡の光を合わせ、合唱を自然に起こす。
4. **「口で答える → なんて こたえた？」の絵札**：文字入力をなくし、ひっかけも崩さない自己申告の型。
