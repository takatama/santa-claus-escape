# 子どもを含む公開GA4計測：設計案

**今回不採用の参考案。** 2026-10-13、本人は[GA4を見送る方針](GA4-OFF-DECISION.md)に同意した。以下の子ども向け計測、同意台帳・専用受付の追加を現在の公開前作業にしない。

2026-10-13 JST。本人が「子どもを含む公開計測の設計」を選んだため、この経路を具体化する。**設計を進める指示であり、計測を有効化する指示ではない。** 本番・評価はOFFを維持する。コード、GA/CFの設定、privacy.html、main、本番配信は変更しない。

運営者は高玉 広和 / Hirokazu Takatama。子ども中心・幅広い年齢、純粋な趣味、無料・収益化なし。米国・EU・英国への積極的な提供を予定し、英語版完成後に英語で紹介する。EU対象国は未定。[確認済みの前提](GA4-SETUP-PROGRESS.md)と[利用条件の判断](GA4-ELIGIBILITY-DECISIONS.md)を引き継ぐ。

以下の「提案」は採用・実装前。「確認事項」は有効化前に判断を残す。中央台帳やCloudflareのデータベースが法律に指定されているという意味ではない。

本人は受付の置き場所として「既存Cloudflareに小さな非公開受付を置く案」を選択した。[Cloudflareの詳細設計案](GA4-CLOUDFLARE-RECEIPTS-DESIGN.md)に保存項目・秘密の控え・運営者認証・期限消去・費用と日常の対応を具体化する。構成と保持期限の採用・実装・有効化は未承認。

## 1. 目的とデータを絞る

目的の提案は、**作品の遊びやすさと共有導線の改善**。個人ごとの能力判定、ランキング、広告、他サイトとの照合には使わない。日常の分析は集計で行い、個人の行動履歴を見る機能は権利対応など必要な場合に限定する。

| 改善の問い | 既存の計測項目 | 解釈の限界 |
| --- | --- | --- |
| 遊び始めた人が結末まで進めたか | `game_start` / `game_complete` | 同意したブラウザの状況。全利用者の完了率ではない |
| どの箱やヒントに改善が必要か | `box_opened` / `hint_revealed`、箱の色・ヒント段階 | 答え・誤入力・自由文は収集しない。子どもの能力を判定しない |
| 紙の謎から先へ進めたか | `spell_completed`、紙の枚数 | 紙の内容、保存データを送らない |
| 中断後どこから戻ったか | `game_resume`、再開場面 | 同じ人・同じ一回のプレイと厳密に対応付けない |
| 共有の導線を操作できたか | `share`、native / copy / manual_copy | 送信相手・SNSアカウント・実際の受信や訪問は分からない |

独自イベントは既存の7種類と許可された値を基礎にし、新しいUser-ID、プレイID、年齢や保護者の役割をGAへ追加しない。既存のカスタム定義5つは設定済みとして扱い、作り直さない。OGP・共有の機能と共有URLをこの設計段階で変更しない。

収集をさらに減らす提案は、初期の公開計測ではGAへ渡す参照元を空にし、計測用page_locationにUTMを含めないこと。紹介元別の効果測定は目的を追加する判断として残す。現在のコードは参照元のoriginと許可したUTMを渡すため、採用時にはその部分だけ別途修正する。

**GA標準の処理も含めて説明する。** page_viewに加え、first_visit / session_start / user_engagement等の自動収集、Cookieのclient_id、GAのセッションID、時刻、言語・端末等を把握する。7種類の独自イベントだけがGoogleへ渡るとは表示しない。[Googleの自動収集項目](https://support.google.com/analytics/answer/9234069?hl=en)。Googleへの通信にIPアドレス等が伴うことと、GAレポートへの保存を区別し、「匿名だから個人情報ではない」と説明しない。

追加の管理設定候補は、両プロパティの**詳細な地域・デバイス情報の収集を全地域でOFF**にすること。Googleの説明では都市、端末のブランド・モデル、細かいOS/ブラウザ版等が対象で、国などのすべての情報や通信を消す設定ではない。[Googleの設定説明](https://support.google.com/analytics/answer/12002752?hl=en)。現在の完了記録にはこの項目がないため、確認済みとはしない。画面操作は次の段階で一つずつ案内する。

同意する人に偏りがあるため、拒否した人・保護者が不在の子どもの状況は分からない。集計を公開する場合も、小人数の組合せや行動履歴を出さず、全児童の傾向・正確なプレイ人数として主張しない。

## 2. リスクと保護者確認を決める

この表は影響評価の下書き。低リスクや適法性を確定したものではない。英国Children's codeが適用される場合のDPIAでは、子どもへの影響・必要性・軽減策を開始前に評価する。[ICOのDPIA説明](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/age-appropriate-design-a-code-of-practice-for-online-services/2-data-protection-impact-assessments/)。法的な対象性と、この作品の設計上の評価を区別する。

| 想定する影響 | 軽減する設計 | まだ評価が必要なこと |
| --- | --- | --- |
| 子どもが内容を理解せず許可する | 短い日英説明、未選択、拒否と許可を同等に扱う、必要な保護者確認 | 年齢・理解度に合う説明と確認方法 |
| 保護者の不在や共有端末で別の人の許可を使う | 前のv1同意を引き継がない。新しいタブで開いた際はOFFから明示選択する案 | 端末の選択から個々の子どもや親子関係を証明できるとは扱わない |
| ブラウザIDで行動が結び付く | 答え・独自ID・広告・詳細地域等を除き、用途と保持を限定 | Google側の処理・再利用・自動収集が目的に収まるか |
| 同意記録や削除依頼が漏れる | GAと分けた非公開受付、運営者認証、本文のログ・通知への転記を抑える | 保存先、契約、保持、監視、バックアップの扱い |
| 取消しや依頼が難しく権利を行使できない | ゲーム内で即時停止、別途の過去データ削除、返信メール不要の受付案 | 対象照合と受付の所要期間・本人確認 |

少人数の操作観察・一般の不具合相談でも改善できる部分は、それを使う。GAが必要な問いを上の表に残し、不要な項目は収集しない。子どもへの負担や第三者処理に見合う利益を説明できない項目は採用しない。

### 同意画面の候補

同意は任意の設定内に置き、拒否・保留でも同じゲームを最後まで遊べる。特典・ゲーム進行・共有を許可の条件にしない。閉じる、無操作、説明を見るだけでは許可しない。

短い説明案：

> このゲームを遊びやすくするため、Google Analyticsで箱やヒントが使われた回数などを調べます。答えや名前は送りませんが、ブラウザを見分けるCookieなどを使います。許可しなくても全部遊べます。いつでも止められます。

選択画面案は「計測せず遊ぶ」「保護者として説明を確認する」「本人として説明を確認する」。役割の選択だけでは送信せず、説明の後に別の許可操作を置く。保護者の画面では「このプレイヤーについて保護者として同意する権限がある」ことも確認する。

本人の選択に使う基準の提案は**16歳以上の自己申告、16歳未満・不明なら保護者経由またはOFF**。これはEU対象国未定で共通画面を考えるための運用案で、すべての国の法定年齢が16歳という意味ではない。生年月日・年齢の数値は保存しない。全員に同じデータ削減を適用し、年齢申告を根拠に子ども向けとしての扱いを解除しない。[EDPBの同意ガイド §7.1](https://www.edpb.europa.eu/system/files/documents/files/file1/edpb_guidelines_202005_consent_en.pdf)。

自己申告だけの保護者確認は条件付きの候補。ICOは特に低リスクの解析では合理的となり得るとするが、GA4・EU全体・米国にそのまま当てはめない。[ICO Annex C](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/age-appropriate-design-a-code-of-practice-for-online-services/annex-c-lawful-basis-for-processing/)。評価で不十分なら、必要な追加確認を具体化してから本人と選ぶ。氏名、身分証、カード、保護者メール、専用アカウントをこの案の初期要件として増やさない。

### 米国の分岐

- まず純粋な非商用の運営と第三者の処理についてCOPPAの対象性を記録する。子ども中心なのでmixed audienceを使うための年齢ゲートとはしない。
- 適用される場合も、内部運用の解析・永続識別子のみ等の条件を満たすか確認する。FTCは条件を満たす第三者の解析も例外に含めるが、GAなら成立するという説明ではない。[FTC FAQ J.5〜7](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions)。広告OFFだけでGoogleの用途制限まで証明しない。自前の受付・同意台帳・秘密の控えも、処理の目的と収集する情報を含めて評価する。
- 現行規則の例外にも内部運用と用途制限の通知がある。古いFAQの「通知も不要」は採用しない。[16 CFR 312.5(c)(7) / 312.4(d)(3)](https://www.ecfr.gov/current/title-16/chapter-I/subchapter-C/part-312)。
- 例外を使えず検証可能な保護者同意が必要なら、役割のクリックで済ませない。第三者への開示の扱い・必要な別同意・確認方法を改めて設計する。Googleフォームや単純なメール確認を当然十分とはしない。同法の氏名・住所・電話・メールの通知要件と、公開メールを使いたくない希望との関係も残る。具体値をチャットやGitへ書かせない。

未解決なら有効化しない。国別制限・本人確認サービスを、ここで勝手に追加する判断はしない。

## 3. 同意を記録し、停止を独立させる

実装候補は次の順序。拒否した人のサーバー台帳を作るために識別子を発行しない。

1. 起動時はOFF。v1のgrantedを新しい説明・保護者同意に読み替えない。GPCが有効、説明の版が旧い、確認が未完了なら開始しない。
2. 許可操作後、非公開受付へ役割（本人/保護者）、説明の版・言語、選択方法、環境を記録する。受付側の時刻を使う。氏名や生年月日を送らない。
3. 記録が受理されたと確認してからGoogleタグを開始する。障害・拒否時はOFFで遊びを続ける。GAを同意記録の唯一の保存先にしない。
4. 既に開始したタグから既存client_idを得られる場合だけ、必要な範囲で同意記録に関連付ける。関連付け失敗時は追加送信を止めて状況を表示する案。取得前にGoogleへ通信が始まることを隠さない。
5. 取消しは先にローカルで送信を止め、待機イベントとGA Cookieを消す。台帳への取消し通知が失敗しても再開しない。ゲームの進行・音設定は維持する。

台帳は当該ブラウザの同意操作を示す記録で、役割の自己申告から実名の親子関係を証明したものではない。説明の全文・画面・版は変更履歴として別に保存する。[ICOの同意記録](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/lawful-basis/consent/how-should-we-obtain-record-and-manage-consent/)。

保存期間の設計候補は、Cookieと同意の見直し期限をそれぞれ60日以内、訪問ごとに明示選択とすること。GAイベント保持2か月は設定済みのまま。中央の同意記録の消去日は、それに対応する処理と必要な証明期間から決める。**同意台帳・集計レポート・Cookie・問い合わせの保持は別**で、すべて2か月で消えるとは表示しない。具体的な台帳期限は保存先と契約・対応範囲を決めて確定する。無期限を初期値にしない。

## 4. 過去データの削除を受け付ける

「今後の計測を止める」と「過去データの削除を依頼する」を別の操作にする。停止を、依頼や確認の完了待ちにしない。

依頼画面を本人が開いた時だけ、まだ端末にある既存client_idを確認する案。許可済みタグのget機能や既存Cookieの読み取りの可否を実装時に検証する。削除のためにタグを新しく読み込んだり、許可を求め直したり、識別子を発行したりしない。Cookieを消す前に本人の操作で依頼対象を保持できる導線を用意し、取消し後に元の識別子が失われる場合も説明する。

受付項目は本番/評価、既存client_id、依頼種別、受付時刻、処理状態を基本とする。自由記述・返信先メールは標準では求めない。一般フォームは一般相談のまま、GA識別子の受付へ変更しない。

メールなしで受付状況を確認するには、**依頼・同意記録の管理だけに使う秘密の控え**を発行する案が必要。これはGoogleへ送る識別子やプレイIDにしない。URLのクエリ・共有URL・計測パラメータへ含めず、サーバー側では照合用のハッシュ等を保持する。目的限定でも新しい認証情報の追加なので、保存先と一緒に採用を決める。秘密の控えや既存client_idだけで、子どもの行動履歴を自動開示する仕組みは作らない。

運営者は非公開の管理画面で対象プロパティとclient_idを確認し、当初はGAユーザーエクスプローラで手動削除する案。ゲームにGoogle管理APIの鍵を置かない。「受付済み」「Googleへ削除依頼を実施」「特定できず追加相談が必要」を区別する。受付をGoogle側の完全削除と表示しない。Googleの説明は探索から24時間以内の非表示、恒久削除63日以内。[Googleのユーザー削除](https://support.google.com/analytics/answer/9283607?hl=en)。集計済みの数字も全部消えるとは約束しない。

受付確認は7日以内、通常の権利対応は1か月以内に進捗・結果を案内する運用目標案。法令ごとの期限・延長の条件とGoogleの処理日数を混同しない。既存の一般問い合わせの「解決後30日以内の削除」は、この受付の保持期限を決めたことにはならない。関連する処理の終了と必要な証明期間に合わせ、client_id、控え、処理記録、バックアップの消去期限を確定する。[個別削除の手順](GA4-DELETION-PROCEDURE.md)。

識別子や控えを失っても相談は受けるが、名前・日付で対象を推測しない。保持期間で既に明細が消えている場合もある。保有データの開示等には、削除とは別に比例した本人/保護者確認を検討する。

## 5. 受付の置き場所と運用負担

**本人が選んだ詳細設計は、既存Cloudflareへ最小限の非公開受付を設ける案。** 同意と権利対応を同じ基盤に置けば、外部サービスを増やすより処理先・保持・閲覧権限を把握しやすい。一方、現在は静的サイトなので、Functions等、保存、運営者認証、保守を追加する変更になる。自己申告の妥当性や契約の問題を、この基盤だけで解決したとは扱わない。

| 候補 | 具体的な範囲 | 運営者の負担 |
| --- | --- | --- |
| Cloudflareの小さな非公開受付 | 同意/取消しの記録、削除依頼、控えによる状態確認、運営者だけの管理。ゲームイベントを独自に集める機能は含めない | 新しいコード・保存先・認証の保守、依頼の確認、GA手動処理、期限での消去・障害対応 |
| 契約条件を確認した外部サービス | 上の記録・権利対応・秘密の受付と保持を満たすサービス。本人確認が必要ならその適合も確認 | 実装を減らせる場合があるが、契約/DPA・子どもの情報・移転・費用・退会時の消去を確認する |

現在の個人用Googleフォームは一般の相談用。Workspaceの処理契約が適用済みとも、台帳・GA識別子受付に適合済みとも判断しない。有料サービス・プランの必要性や費用をまだ確認していないため、無料で収まるとも有料契約が必須とも断定しない。

Cloudflare案を採用する場合の境界は、管理者のみの閲覧、サーバー側の入力検証、環境の分離、受付URLへ識別子を出さないこと、秘密の保護、最小限のログ、悪用防止、保持期限での消去。第三者のボット対策やメール通知へ依頼本文・client_idを渡す機能は自動追加しない。Cloudflareが配信・安全性のために扱う通信情報は別に確認する。運営者が依頼を確認できない状態では公開計測を開始しない。

## 6. 一つずつ進める順序

1. **受付の置き場所はCloudflare案を選択済み。** 設計の前提で、実装・契約・計測の承認ではない。
2. [Cloudflareの詳細設計案](GA4-CLOUDFLARE-RECEIPTS-DESIGN.md)に沿い、保存項目・期限・控え・運営者認証・日常の処理を確定する。本人は受付の存在だけの通知を選び、[Apps Scriptによる通知の設計](GA4-NOTIFICATION-DESIGN.md)へ進む。増える実装を一覧にし、採用範囲を本人と決める。
3. データ削減後の影響評価と対象地域の適用判断を完成し、保護者確認の方法を決める。Googleの利用条件・処理/移転、必要な連絡先・代理人等の該当性も具体化する。EU対象国未定を放置して全地域適合としない。
4. 日英の詳細通知と画面の文言を実際の構成に合わせて完成する。対象となる子ども・保護者にも理解しやすいか確認する。
5. 承認された範囲だけ実装し、モックで同意前・拒否・取消し・期限切れ・障害・権限・環境分離を検証する。その後の実GA送信試験は別途明示的に判断する。
6. 未解決の条件と運用の準備を確認した後で、本番有効化の判断を別途行う。mainマージ・本番公開はこの設計作業に含まれない。

成人の運営者本人だけの評価は、後で技術を確認する選択肢として残すが、公開の子ども計測設計を先に進めるという今回の選択を置き換えない。
