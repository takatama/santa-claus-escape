## 音と見た目の検証範囲

代表3本のAAC/Opus比較は [audio-samples.json](audio-samples.json) と [browser-audio-samples.json](browser-audio-samples.json)。AACはデコード長を維持し、代表のRMS差は約-0.05〜+0.02dB。AAC 64kbpsを採用、BGM代替は128kbps。Opusは小さいが旧SafariのOgg対応差を考慮して採用しなかった。AACが再生できない環境には従来の文字／ブラウザ読み上げへの退避が残る。

全69本のAACをChromium Web Audioで実際にデコードし、原本との長さとチャンネル数を確認した [decoded-aac.json](decoded-aac.json)。0000 / 0123 / 8849 / 2502を実際のjoinAudioBuffersで連結し、原本との差は1サンプル（約0.021ms） [number-joins.json](number-joins.json)。順序、0.08秒の間、無音ガードのアルゴリズムは変更しない。

画像は原寸・WebP品質85を基本、球・サンタ・まほう使いは95。全透過のアルファを画素ごとに一致確認。森・球・赤い箱の代表比較を視認し、雪・ガラス・輪郭に大きな差を認めなかった。細い文字の手がかりは既存のcanvas文字のまま。寸法を変えず、絵の構図・アニメーション・操作座標を維持する。

人間による聞き取り、端末のスピーカーでの音量、数字の継ぎ目、Safari/Android/LINEの実機、子どもの初見試遊は未確認。機械的なデコードやサンプル数一致を主観的音質の保証に置き換えない。公開記事は比較環境とこの制約を掲載する。

## 再現

通常のnpm run buildはコミット済み派生素材を許可リストからdistへコピーするだけで、CloudflareにFFmpeg/Pillowを追加しない。変換を再現するときだけ `python scripts/optimize-media.py --samples --ffmpeg <path>` → 比較 → `--all`。`npm run check:media`で原本・派生のハッシュを確認。配信形式を変えるときは以前のdistを別保存して新しいdistを作る（未知のファイルをビルドが黙って削除する挙動は加えない）。

`node scripts/measure-performance.mjs before <before-dist>`、`node scripts/measure-performance.mjs after dist`、`node scripts/summarize-performance.mjs`。FFmpegは9.0.2、画像はPillow 12.3.0。Google/APIへの音声再生成呼出しは行わない。
