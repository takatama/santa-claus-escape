# GA4個別データの削除依頼手順

2026-10-12。運営者向けの手順。Googleの画面で削除を実施した記録ではない。依頼受付・対象特定の仕組みはまだ整備済みではなく、本番計測を有効化する前に解決する。

2026-10-13更新：[問い合わせフォーム](CONTACT-FORM.md)による非公開の相談窓口を用意し、ローカルのprivacy.htmlへ反映した。以下の「受付先は未決定」は作成時点の記録。現在のフォームはCookie/client_idを入力しないよう案内しており、GAデータの安全な対象特定・削除依頼の手順は未完成。フォームへの問い合わせ回答の削除と、Google Analytics上のユーザーデータ削除を混同しない。

## 三つの処理を分ける

| 処理 | 操作・設定 | 範囲 |
| --- | --- | --- |
| 今後の計測を止める | ゲームの「計測を許可しない／許可を取り消す」 | 送信停止とこの端末のGA Cookie削除。進行保存は維持 |
| 保持を短くする | GA管理→データの収集と修正→データの保持→2か月 | ユーザー・イベントデータの保持。通常の集計レポートは同じ期限で一律に消えるものではない |
| 既に送信した個別データを削除する | GAの探索→ユーザーエクスプローラ→対象→ユーザーを削除 | 対象のブラウザ識別子に関連付けられたデータの削除依頼 |

公式：[データの保持](https://support.google.com/analytics/answer/7667196?hl=ja)、[ユーザーエクスプローラ](https://support.google.com/analytics/answer/9283607?hl=ja)。

## 有効化の前に決めること

1. 非公開でやり取りできる受付先（例：運営者の連絡用メール）を決め、privacy.htmlへ記載する。現状のGitHub公開Issueへ名前、メール、Cookie、client_id等を書かせない。受付先は未決定であり、この手順の作成だけでは解決しない。
2. 必要な情報は対象サイト／本番か評価か／そのブラウザのGA標準client_id。氏名・答え・身分証で照合する仕組みはない。独自のUser-ID・プレイIDを追加しない。
3. 依頼者がclient_idを安全に確認・提出する手段を用意する。現在のゲームUIには専用の表示・依頼機能がない。Cookieを先に消すと元の識別子を復元できず、名前・訪問日時だけで該当者を確実に特定できない。特定できない場合の説明・対応も決める。個別データを必ず特定して削除できるとは約束しない。
4. 受付から返信までの運用を決める。連絡情報をGAへ送らず、公開のIssue、記事、Gitの記録へも残さない。

## 本人の評価で削除操作を試す

成人の本人だけで、規約・同意を確認済みの評価を行う場合の手順。初めは本番ではなく評価プロパティを使う。

1. 評価用 `G-B2YBCVGPDD` のタグが既に動き、計測を許可した自分のブラウザで、**Cookieを削除する前に**DevToolsのConsoleから次を実行する。既存のGA標準識別子を確認するための操作で、新しいカスタム識別子は作らない。

   ```js
   gtag('get', 'G-B2YBCVGPDD', 'client_id', value => console.log(value));
   ```

   [Googleタグのget仕様](https://developers.google.com/tag-platform/gtagjs/reference#get)。値は公開しない。タグが未設定・未ロード・ブロックされていると取得できない。失われた過去の識別子を得るために新たに許可したり、新しいCookieを発行したりしない。この開発者向け確認手順だけで一般利用者の依頼導線が整ったことにはならない。

2. ゲームで許可を取り消して今後の送信を止める。
3. GAで評価プロパティを選び、編集者以上の権限があることを確認する。管理→データの表示→レポート用識別子を必要に応じ「デバイス別のみ」にする。本作品はUser-IDを送らず、ウェブのデバイスIDはclient_idに相当する。
4. 探索→テンプレートギャラリー→ユーザーエクスプローラ。利用した期間を選び、デバイスID／有効なユーザーIDで自分のclient_idと一致する記録を選ぶ。日時だけで推測して別人を選ばない。
5. 対象を再確認し、右上の「ユーザーを削除」→警告画面の「削除」。Googleへの削除依頼は取り消せない操作なので、運営者本人が実施する。
6. 受付日・対象プロパティ・実行日・状態を必要最小限の非公開の運用記録へ残す。Google公式では探索から24時間以内に表示されなくなり、その後63日以内に完全削除されると説明している。即日完全削除を約束せず、集計済みの人数等が全部消えるとも説明しない。

## 本番の依頼を受けた場合

受付先と対象確認手段を整備した後、上の手順を本番 `G-MHGWR7DQGB` に対応するプロパティで行う。依頼者のブラウザのclient_idとプロパティを取り違えない。運営者自身のclient_idを代用しない。識別子が既に失われている場合はその事実を説明し、対象を推測して削除しない。

管理→「データ削除リクエスト」は、特定期間のイベントパラメータの文字列等を削除するための機能で、今回の個別ユーザー削除の入口は「ユーザーエクスプローラ」。個別依頼を理由に、全員のデータを削除する設定を勝手に選ばない。[Googleのデータ削除リクエストの説明](https://support.google.com/analytics/answer/9940393?hl=ja)。

## プライバシー表示と合わせる

受付先・対象特定方法・処理範囲・所要期間・特定できない場合の対応を、実際の運用に合わせてprivacy.htmlへ反映する。それまでは未整備と記載し、Productionの承認フラグをfalse／未設定のまま維持する。子ども利用の適用条件はこの削除手順とは別に確認する。
