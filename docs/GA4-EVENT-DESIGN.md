# アクセス・プレイ計測設計

**今回不採用の参考設計。** 2026-10-13、本人は[GA4を見送る方針](GA4-OFF-DECISION.md)に同意した。準備コードは無効のまま残し、以下のイベント収集と分析を今回の公開では実施しない。

2026-10-12。基準実装は `231e3de`。Googleタグ（gtag.js）のみ使用し、実行時の生成AI・バックエンド・独自識別子を追加しない。

## 有効化の条件

測定ID未設定、ローカル、本番IDが設定されたプレビュー、適用条件の承認未設定、利用者が未選択／拒否の場合はGoogleタグを読み込まない。Cookieなしのpingも送らない（basic consent方式）。同意前のゲームイベントは保持・後送しない。許可していない人も同じゲームを最後まで遊べる。

本番は `CF_PAGES=1`、`CF_PAGES_BRANCH=main`、`SANTA_GA4_ID`、`SANTA_GA4_POLICY_APPROVED=true` と本番originの完全一致で有効化候補となる。さらに利用者が「計測を許可する」を選択して初めてタグを読む。GPCが有効なら無効。本番URLは `SANTA_PUBLIC_URL`（未設定は現在のPages URL）。プレビューの検証は別ID・別originだけを明示設定する。[設定手順](GA4-SETUP-JA.md)参照。

## イベント

| イベント | パラメータ（送信する値） | 発火条件 | 分析 |
| --- | --- | --- | --- |
| `page_view` | Google標準。固定タイトル、ルートURLと許可したUTMだけ、参照元はoriginのみ | 許可後のGoogleタグconfigで一回。手動page_viewは送らない | 計測に参加した閲覧者、流入 |
| `game_start` | 追加なし | welcome→introの実遷移。リセットだけでは発火せず、その後開始したとき | 開始ユーザー、開始回数 |
| `game_resume` | `resume_phase`: intro / boxes / box / boxResponse / spell / witchInvite / witchPaused / witchQuestion / witchResponse / rescue / complete | 保存復元後、本人が「続きから遊ぶ」を押す。文書一回につき最大一回 | 再開利用者、保存された到達地点 |
| `box_opened` | `box_color`: red / blue / yellow | 正しい数字を試し、閉じた箱が解錠済みになる実遷移 | 各色を解けた人数。ふたを閉じて開き直す操作では増えない |
| `hint_revealed` | `box_color`、`hint_step`: 1 / 2 / 3 | 「調べる」でexamが1→2、2→3、3→4へ進む実遷移 | 既存の段階的手がかりを何段階調べたか。初めて箱に入るだけでは発火しない |
| `spell_completed` | `paper_count`: 0 / 2 / 4 / 6 | SPELL成功→witchInvite。合言葉の入力自体は送らない | ひみつの言葉への到達。原作の早期ルートも数える |
| `game_complete` | 追加なし | rescue→completeの実遷移。旧いreleased救出保存の再開時のFINISHでは送らない | 救出へ到達した人数 |
| `share` | `method`: native / copy / manual_copy、`content_type`: game、`item_id`: santa-claus-escape | P2の共有API成功／URLコピー成功／本人が手動コピー完了を確認 | 共有導線の利用。共有先のアプリ名、相手、メッセージ、実際に届いたかは計測しない |

`box_opened`はここでは解錠成功を指す。物理的なふたの開閉・アニメーション完了は進行指標にしない。`hint_revealed`は新しい救済ヒントを追加するものではなく、現行の三段階の「調べる」を観測する。色の順序は自由であるため、赤→青→黄の固定順ファネルを作らない。

## 重複・配信・互換性

既存 `extractGameEvents` とbefore/afterの実状態を利用。再読み込み、保存復元、読み返しの投影、UI再描画、音量設定、入力編集、古いrevisionのクリックをイベントにしない。救出はonProgressからも観測する。セーブキー `santa-claus-escape:ja-full:v2`、version 2、保存本文は変更しない。計測用フラグをゲーム保存へ加えない。

既にcompleteの保存を開いたときは `game_resume` のみ。旧版の救出済み保存の整理は新たな完了とみなさない。同意の設定は別の固定キーで保持し、リセットでゲーム進行と一緒に消さない。複数タブで独立に同じ保存から遊んだ場合はそれぞれの実操作を数える。独自IDによる跨タブの厳密な一回化は行わない。

タグは非同期。通信・タグロードの成否をゲーム進行、音声開始、保存、共有成功の条件にしない。タグロード中のイベント予約は32件まで、タグ失敗時に破棄。広告ブロッカー等で欠測があり、送信済み・受信済みの厳密な保証はない。リトライによる二重送信を追加しない。

## 収集しないもの

謎の答え、数字、合言葉、自由入力、質問への回答、履歴本文、氏名、メールアドレス、録音、独自のユーザー／プレイID、時刻をカスタムディメンションとして送らない。イベントと値を許可リストで絞る。任意URLのquery/hashを送らない。UTMは friend / line / x / qiita / github / game_share / social / referral / release2026 / ending / copy / native / manual_copy の既知ラベルだけ。追加する場合は個人名を含まない運営用ラベルをコードレビューする。

GA標準のCookie識別子や端末情報は処理されるため「匿名だから同意不要」とはしない。広告パーソナライズ、Googleシグナル、User-ID、広告連携、拡張計測のフォーム・クリック・検索は使わない。[プライバシー条件](GA4-PRIVACY-REVIEW.md)を参照。

## レポートの定義

| 指標 | 推奨する計算・探索 | 制約 |
| --- | --- | --- |
| 新規開始率 | 同期間の閉じたファネル page_view→game_start の開始到達ユーザー割合 | 同意したユーザーのみ。PVの数で割ると再読込の影響が出る |
| 新規開始からのクリア率 | 閉じたファネル game_start→game_complete のユーザー到達割合。間接的に続くステップ、期間を明記 | 同一人物の再プレイを分けない。日を跨ぐプレイは期間に依存 |
| 再開利用 | game_resumeのユーザー数とイベント数、resume_phase別 | 初回開始とは別集団。completeの再開は再プレイではない |
| 箱の到達 | 各色のbox_openedのユーザー数÷game_startまたはgame_resumeユーザー（どちらを分母にしたか明記） | 独立した色別集計。開始した人と再開した人を単純に合算しない |
| 手がかり利用 | hint_revealedのユーザー・イベント数を色と段階で比較 | 初回入箱時のexam1は含まない。全員が手がかりを全部使う前提にしない |
| 共有利用 | shareユーザー数、method別件数 | コピー成功は相手への配信成功ではない |
| 流入比較 | セッションの参照元／メディア、キャンペーンで上のファネルを比較 | SNS内ブラウザのreferrer欠落、Cookie制限、同意率差あり |

厳密なゲーム1回ごとの完走率、プレイ時間、個別プレイの横断追跡は今回のデータからは求めない。イベント数 `game_complete / game_start` は参考値に限り、期間内の再開や複数回プレイが混じるため100%を超えることもある。公開記事では、対象期間、母数、同意による欠測、比較条件、既存保存ユーザー、ブラウザ検査と実機の違いを併記する。

品質イベント候補：音声取得／decode失敗を一ページ・種類あたり一回の `audio_load_failed` で記録する案。OSの自動再生拒否、利用者の停止、実際のネットワーク障害を区別する必要があるため今回は未実装。URL・台詞・入力数字・エラー全文は送信しない。別の必要性判断に回す。
