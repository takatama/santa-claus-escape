# PR A：赤い箱の統合方式の検証

最終仕様は [Issue #3](https://github.com/takatama/santa-claus-escape/issues/3)。このPRは赤い箱をmainの音声・進行・保存へ接続する最初の縦断実装です。Issue全体の完成、mainへのマージ、本番公開は含みません。

## 調査と変更範囲

- 基準：main `e4d225b`。`prototype/full-game.js` が状態、`full-scenario.js` が原文・答え・紙、`speech.js` / `audio-timeline.js` / `soundtrack.js` が声と音を管理。保存キーは `santa-claus-escape:ja-full:v2`。
- [PR #1](https://github.com/takatama/santa-claus-escape/pull/1) `aead6e9` はページごとの音声なし試作。別のjourney保存・謎モデルは移しません。箱の本体・ふた・たぬきの三枚の画像、`cylinder-lock.js`、段階式 `snow-reveal.js`、ヒンジの計算、メッシュ描画、赤い箱の描画部分を取り出しました。
- [PR #2](https://github.com/takatama/santa-claus-escape/pull/2) `94f2a82` のPRODUCT-DESIGN §8と実プレイ所見を参照。大きい舞台、場面名のある主操作、暗転しない同一ページ、触れなくても進める操作を採用。音の設定は上部、台詞はユーザーの追加要望に沿って常設。4夜・保護者の役割・合言葉の儀式は追加しません。
- 赤い箱だけ `red-box-stage.js` を使います。導入・三箱選択・青黄・言葉・三問・救出はmainの既存画面。URLも保存キーも同じです。
- 表紙・導入を表示する間に絵を準備し、箱選択後の読み込み待ちを減らします。一度の読み込みを再利用し、雪・解錠・ふたの各操作で再取得しません。低速回線で選択が先に来る場合は読み込み表示が残り得ます。
- 配信許可リストに新しい実行ファイルと三枚の絵を追加。検査・制作資料は配信しません。実行時依存や外部APIは増えません。Playwrightはテスト専用です。

## 操作と音・保存

1. 赤い箱を選ぶと原作の第1段階。主操作で第2（文字）、第3（たぬき）、第4（たに×）へ、一押し一段階。PR #1の雪の質感、横に払う軌跡、落ちる雪片、各段階1700 / 1900 / 1150msの速度を再利用。雪に指を動かしても段階は進めず、自由こすりには戻しません。低減モーションでは雪片を出さず即表示します。
2. ナレーション中も操作を受け付け、箱の状態はその場で進みます。「調べる」は現在の声を切らず、次の声と効果音を一列に再生。連続した同じ台詞は予約を重ねません。**「ためす」は再生中の声・効果音と予約済みの調査・判定を破棄し、最新の4桁の判定へ切り替えます。** 同じ数字で再試行した場合も結果を読み直し、古い終了通知から台詞を復活させません。数字の変更だけでは判定せず、声も取り消しません。雪の演出中だけ次の進行操作を保留し、一押し一段階を守ります。字幕欄には大きなスピーカーと動くバーで「声を再生中」を表示。バーは再生状態のアニメーションで、実音量の測定やマイク入力ではありません。低減モーションでは動きを止めます。
   台詞は縦画面の下段、横長画面の右側に常設し、全文を内部スクロールで読めます。先行操作した時は「再生中」「このあと」で現在の声と予約済みの台詞を残します。停止・ミュートでは予約も破棄し、再生不可でも文字で続けられます。数字操作・音声切替では読んでいた位置を保ち、台詞が変わった時だけ本文を先頭へ戻します。旧セーブの字幕を閉じる設定も書き換えません。
3. PR #1の絵と操作を、縦横同じ倍率で描く拡大表示へ接続。調査中は箱・錠・ヒントの大きさを固定し、窓が狭い時は周辺の装飾を切り取ります。錠は280×144 CSS px、ヒントは300×約125 CSS px。錠は箱の面に取り付けた4つのダイヤルが唯一の表示・編集箇所。上下矢印の絵は出さず、隣の数字のタップ、ドラッグ、数字キー、上下左右キーが同じ値を編集。「ためす」は錠の直下。別の入力欄・入力方式切替はありません。
4. 「ためす」は最初の段階から「調べる」と同じ明るい色・厚み・押下時の沈み込みで、押せることを示します。ヒントとの間に余白を確保。「調べる」はヒントの直下へ寄せ、低く狭い画面では箱のすぐ下に置きます。誤答はその場で画面と既存音声で通知。どの調査段階でも正解を試せます。解錠後も同じダイヤル錠の姿を残し、数字だけ編集不可にします。チェックマークへの置換と、雪の上に重ねていたふたの金色の輪郭線は削除しました。
   ふたは解錠だけでは開きません。PR #1の縁の矢印を、つまみの形と上向きの反復運動を持つ一つの操作点へ移植。指に沿って動き、途中で止めて戻せ、途中位置も保存します。全開時は下向きに変わります。同じつまみをタップ・Enter・Spaceでも操作でき、画面下の開閉ボタンと追加の説明文は取り除きました。原作の台詞は字幕に残します。ドラッグ終了とタップを二重に処理せず、低減モーションでは方向の矢印を静止。開閉で操作欄の高さを変えず、ドラッグ中に箱の倍率が跳ねることを防ぎます。
5. 元の成功タイムラインを、紙発見の効果音の直前で分割。声と音は数字確認 → 解錠音 → 開箱宣言 → 正解音 → 紙の台詞の順。ふた操作を先に行っても、正解音と紙の声は解錠の声の後へ予約します。ふた操作前に紙の声は予約しません。新しい台詞、音声生成、結末の鈴はありません。分割した両方をつなぐと既存タイムラインと一致します。
6. `opened` と紙の二枚の授与はmainの既存の正解時の状態遷移を保持。ふた位置は表示用の追加情報で、閉じても二枚の紙は消えません。旧セーブの開封済みはふたを開いた状態へ、未開封の有効な直接入力はダイヤルへ引き継ぎます。
7. 再読み込みは既存の「続きから遊ぶ」。やり直しは既存の確認ダイアログ。保存不可でもページを開いている間は進行できます。

## 技術的リスクと限界

- PR #1の状態管理まで移すと二重の保存・紙授与が起きるため、描画と操作だけを移植。mainの全六順序・全問誤答・辞退と呼び直しの検査を維持します。
- 音声予約はゲーム状態に保存しません。再開ではその時の場面を読み、停止・ミュート・箱から戻る操作は予約を破棄します。聞き直しは現在の場面を再生。古い音声終了の扱いは既存SpeechPlayerに任せます。先行操作が多い時は見た目より声が遅れますが、予約済みの台詞も読めます。予約後の再生が操作イベントの外で始まるため、既存のWeb Audioコンテキストを最初の操作時に準備します（[Chromeの自動再生の説明](https://developer.chrome.com/blog/web-audio-autoplay/)参照）。音声・効果音の読み込みや再生は予約の順番が来るまで始めません。
- 三枚のPNGは合計 **6,112,300 bytes（約5.83 MiB）**。箱の調査では森・球・枝を使わないため、その三枚を配信と先読みから除外。元ファイルとSHA-256一致を確認し、無加工で配信。低速回線、低性能端末での読み込み・描画性能は未確認。画像失敗時は既存の原文字幕とダイヤルで進行できます。
- ふた途中の位置は追加保存しますが、旧mainは追加フィールドを無視できる方式。旧直接入力の数字以外の未完成文字列はdraftに保持し、ダイヤルでは最後の有効な4桁を表示します。
- 錠と手がかりは箱と共通の座標で位置を決め、ふたの継ぎ目より下に錠を重ねます。短い横画面では手がかりと錠を左右に配置。さらに低く狭い窓では箱の領域も縦にスクロールでき、台詞と主操作は窓内に残ります。箱本体は元画像の透明余白を除いた比率、ヒントと雪は620×258の比率を維持。雪の質感は再描画せず同じマスクを再利用します。
- 解錠後だけ650msで視点を引き、同じ比率の箱・ふた・紙を全体表示へ移します。カメラは保存や謎とは別の表示情報。再開済み・低減モーションでは即表示し、ふたの途中位置は従来どおり保存します。全開のふたも画面内に収めます。全編の画面統一は後続PRです。

## 検証

2026-10-10のローカル検査：通常テストは49件成功、原本との直接照合2件は明示的スキップ。Chromium E2Eは13件成功。design / audio / publication / build / pages / 差分の空白検査も成功（CIと配信先の最新結果はPR本文に記録）。公開リポジトリには非公開原本がないため、直接照合のみ省略し、公開済みシナリオの状態・音声・答えの検査は実行します。

```sh
npm ci
npx playwright install chromium
npm test
npm run check:design
npm run check:audio
npm run check:publication
npm run build
npm run check:pages
npm run test:e2e
git diff --check
```

E2EはPages用成果物をChromiumで検査します。雪の連打、自由こすりで進まないこと、払い途中と雪片、錠の箱上の位置・ヒントとの余白・近くの調べるボタン、数字キー・矢印キー・ドラッグ・タッチ入力、誤答、早期解錠、ふた開閉と途中位置、つまみの方向表示・途中で離しても全開にならないこと・中断・Enter/Space・タッチのタップ代替、解錠後も残るダイヤルとつまみが数字を隠さないこと、紙、旧保存、再開、初期化確認、音声中の操作・動く再生表示・録音の自然終了と効果音の順序・予約の停止、BGM、字幕、低減モーション、画像・音声・保存の失敗を対象にしています。導入から青黄を含む三箱、辞退・呼び直し、全問誤答で原作の結末に進む回帰確認も含みます。

「ためす」の回帰検査は、調査音声中の試行、同一タスク内の連打、異なる誤答→同じ誤答の再試行→正解を対象にします。音声・効果音の両ソースの停止、未再生の調査音声の破棄、字幕の置換、旧ソースの終了コールバックが最新の声を止めないこと、ふたが勝手に開かないこと、紙が二重授与されないことを確認します。テスト内だけ再生速度を調整し、実際の音声ソースと終了イベントを使います。

表示確認：320×568、390×844、844×390、768×1024、1024×768、1280×720。スマホ寸法とタッチエミュレーションは実機確認ではありません。

画面サイズ変更後はResizeObserverによるCanvasの再描画を待ってから座標を検査します。箱の比率と錠・ヒントの大きさが変わらないこと、台詞を閉じた旧セーブでも常設表示されること、キーボードで台詞だけをスクロールできること、数字・音声操作で読んでいた位置を保つこと、先の段階のヒントを台詞で開示しないことを検査。568×320の短い横画面でも、箱の内部スクロールから解錠・ふた・紙の台詞・継続まで確認します。
